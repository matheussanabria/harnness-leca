# 1. Identificação
- **História:** 08.01 — Extensão de Extração Local com `--engine ollama`
- **Arquivos Alvo:** `tools/extract-artifacts.js`, `tools/lib/llm.js`, `tools/lib/runtime/ollama-cli.js`, `tools/lib/runtime/ollama-client.js`

# 2. Contexto
`tools/extract-artifacts.js` já aceitava `--engine claude` e `--engine opencode`. Ambos consomem cota ou exigem credencial. A extração de artefatos é rotineira e roda sobre conversas inteiras: executá-la localmente reduz custo e latency.

# 3. Objetivo
Permitir `node tools/extract-artifacts.js --project <slug> --llm --engine ollama [--model qwen3.5:4b]`, mantendo o mesmo formato de saída em `projects/<slug>/context/extraido-memorias.md`.

# 4. Requisitos
- **RF-01:** `--engine ollama` é aceito na validação de argumentos da CLI.
- **RF-02:** O nome do modelo local aceita a tag de versão (ex.: `qwen3.5:4b`).
- **RF-03:** A resposta do motor local é texto livre (Markdown), coerente com o prompt da CLI — sem `format: json`.
- **RF-04:** Falha do daemon local interrompe apenas a conversa em processamento; a conversa permanece pendente e nada é gravado em `memory.md`/`instructions.md`.
- **RF-05:** A bridge `ask()` é síncrona, mas o cliente HTTP é assíncrono: a chamada local é feita em processo próprio (`ollama-cli.js`) lendo o prompt no stdin.
- **RNF-01:** Nenhuma chamada a motor em nuvem quando o motor local falha.

# 5. Arquitetura
- `tools/lib/llm.js` — `askOllama()` executa `node tools/lib/runtime/ollama-cli.js --model <modelo>` com o prompt no stdin.
- `tools/lib/runtime/ollama-cli.js` — chama `generateText` e escreve a resposta no stdout.
- `tools/lib/runtime/ollama-client.js` — `generateText` (sem `format`) e `generateStructured` (com `format: "json"`), sobre um `request()` comum.

# 6. Implementação Passo a Passo
1. Extrair a requisição HTTP comum em `request()` no cliente do runtime.
2. Implementar `generateText` para respostas em texto livre.
3. Criar `ollama-cli.js` como runner do prompt via stdin.
4. Reescrever `askOllama` em `tools/lib/llm.js` para usar o runner, sem script inline.
5. Aceitar `ollama` na lista de motores e permitir `:` no nome do modelo.

# 7. Testes Pré-definidos
- `generateText` não envia `format` e devolve o texto bruto.
- `generateStructured` mantém `format: "json"`.
- O runner devolve a resposta do daemon e repassa o prompt pelo stdin.
- `ask({ engine: "ollama" })` devolve o texto do daemon local.

# 8. Critérios de Aceite
- [x] `--engine ollama` executa de ponta a ponta com daemon local mockado.
- [x] A saída mantém o mesmo formato Markdown das demais engines.
- [x] Falha do daemon não apaga nem grava memórias.

# 9. Riscos
- `ask()` síncrono exige processo filho; o custo de spawn é relevante quando há muitas conversas. O estado de pendência garante retomada sem perda.
- Modelos compactos podem divergir do formato Markdown esperado; a revisão humana continua obrigatória (o arquivo é sempre sugestão).
