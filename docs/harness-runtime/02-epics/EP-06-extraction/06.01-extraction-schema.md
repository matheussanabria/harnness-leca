# 1. Identificação
- **História:** 06.01 — Contrato Estrito de Extração de Conhecimento
- **Arquivos Alvo:** `schemas/runtime-extraction.schema.json`, `tools/lib/runtime/extractor.js` (validador)

# 2. Contexto
O runtime local precisa devolver conhecimento estruturado de forma previsível, para que a mesma saída possa ser gravada em `projects/<slug>/context/` e consumida por ferramentas sem revisão manual do formato.

# 3. Objetivo
Definir e validar um contrato com quatro campos obrigatórios: `decisoes`, `regras`, `termos` (arrays de strings) e `resumo` (string não vazia).

# 4. Requisitos
- **RF-01:** Os quatro campos são obrigatórios; a ausência ou tipo incorreto invalida o payload.
- **RF-02:** `decisoes`, `regras` e `termos` devem ser arrays; itens são normalizados para string e removidos quando vazios.
- **RF-03:** `resumo` deve ser string não vazia após `trim`.
- **RF-04:** Propriedades não declaradas são rejeitadas (`additionalProperties: false`).
- **RNF-01:** Validação determinística, sem dependência de rede ou modelo.

# 5. Arquitetura
Validador puro (`validateExtraction`) separado do serviço de inferência, retornando `{ valid, errors, value }`.

# 6. Implementação Passo a Passo
1. Criar `schemas/runtime-extraction.schema.json` com os quatro campos e `additionalProperties: false`.
2. Implementar `validateExtraction(data)` em `tools/lib/runtime/extractor.js` com acumulador de erros.
3. Retornar `value` normalizado apenas quando não houver erros.

# 7. Testes Pré-definidos
- Payload válido retorna `valid: true` e `value` idêntico ao payload.
- Payload com `decisoes` não-array e `resumo` vazio retorna `valid: false` com ao menos 2 erros.

# 8. Critérios de Aceite
- [x] Contrato documentado em JSON Schema.
- [x] Validador cobre arrays, strings e ausência de campos.
- [x] Erros são descritivos e listados por campo.

# 9. Riscos
- Modelos pequenos podem devolver campos extras; o `additionalProperties: false` documenta a intenção, mas a normalização do serviço aceita apenas os quatro campos conhecidos.
