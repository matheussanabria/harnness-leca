# 1. Identificação
- **História:** 06.02 — Serviço de Extração Estruturada Local via Ollama
- **Arquivo Alvo:** `tools/lib/runtime/extractor.js`

# 2. Contexto
As conversas dos projetos contêm decisões, preferências e vocabulário de domínio que hoje dependem de LLMs em nuvem para serem destilados. O runtime local deve executar essa tarefa sem cota e sem ferramentas habilitadas.

# 3. Objetivo
Implementar `extractKnowledge({ text, model, signal })` que executa uma inferência estruturada no Ollama, valida o resultado e devolve `{ success, extraction, metrics, errors }`.

# 4. Requisitos
- **RF-01:** Prompt de sistema determinístico que especifica exatamente os quatro campos esperados e exige resposta apenas em JSON.
- **RF-02:** Inferência com `temperature: 0.1`, `numPredict: 512`, `numCtx: 4096` e `think: false`.
- **RF-03:** Texto vazio ou não-string resulta em falha controlada, sem chamada de rede.
- **RF-04:** Falha do Ollama é capturada e devolvida em `errors`, sem exceção escapar.
- **RF-05:** Métricas nativas da inferência (tokens de prompt/geração, durações) são propagadas em `metrics`.
- **RNF-01:** Arquivo com menos de 150 linhas.

# 5. Arquitetura
Serviço stateless sobre o cliente HTTP do runtime; a dependência `generateStructured` é injetável via mock de `globalThis.fetch` nos testes.

# 6. Implementação Passo a Passo
1. Definir `EXTRACTION_SYSTEM_PROMPT` com a instrução de formato JSON.
2. Montar o prompt do usuário com o texto analisado entre delimitadores.
3. Chamar `generateStructured` e submeter a resposta a `validateExtraction`.
4. Propagar `metrics` em sucesso e em falha de validação.

# 7. Testes Pré-definidos
- Mock de `fetch` devolvendo JSON válido resulta em `success: true` e métricas de tokens.
- Texto vazio retorna `success: false` com erro descritivo.

# 8. Critérios de Aceite
- [x] Extração produz decisões, regras e termos a partir do texto.
- [x] Falha de validação do modelo é reportada sem quebrar o chamador.
- [x] Nenhum dado de entrada é gravado em log de telemetria.

# 9. Riscos
- Modelos compactos podem gerar JSON inválido; a validação estrita converte o problema em erro legível em vez de dado corrompido.
