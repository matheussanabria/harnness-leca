# 1. Identificação
- **História:** 05.01 — Suíte de Testes Unitários e Integração com Mocks
- **Arquivo Alvo:** `test/runtime-local.test.js`

# 2. Contexto
Garantir que todas as camadas do runtime local (adapter, validador, classificador, interceptor e telemetria) sejam testadas exaustivamente de maneira reproduzível e isolada, sem depender de conexão real com o daemon local durante o CI/testes locais.

# 3. Objetivo
Criar `test/runtime-local.test.js` cobrindo cenários de sucesso, erro de validação, indisponibilidade e timeouts.

# 4. Requisitos
- **RF-01:** Testar resposta válida e parsing do schema estrito.
- **RF-02:** Testar resposta com JSON malformado ou campos inválidos.
- **RF-03:** Testar daemon Ollama indisponível (conexão recusada / ECONNREFUSED).
- **RF-04:** Testar timeout e abort de requisição.
- **RF-05:** Testar registro correto de métricas na telemetria.
- **RNF-01:** Execução limpa via `node --test` ou framework de testes do projeto.

# 5. Arquitetura
Testes modulares utilizando interceptação nativa de `fetch` global ou mocks de resposta HTTP.

# 6. Implementação Passo a Passo
1. Criar `test/runtime-local.test.js`.
2. Implementar helpers de mock de fetch.
3. Testar cada módulo isoladamente e em conjunto.

# 7. Testes Pré-definidos
- Executar `node --test test/runtime-local.test.js`.
- Executar `npm test`.

# 8. Critérios de Aceite
- [ ] 100% dos testes passando sem dependência de hardware externo.
- [ ] Cobertura de cenários extremos e falhas de rede.

# 9. Riscos
- Mocks não refletirem fielmente o payload do Ollama: basear fixtures diretamente na documentação e no benchmark recente.
