# 1. Identificação
- **História:** 03.01 — Interceptor Passivo de Shadow Mode
- **Arquivo Alvo:** `tools/lib/runtime/shadow.js`

# 2. Contexto
Para avaliar o comportamento da classificação local em produção sem riscos, as requisições enviadas ao chat serão analisadas em paralelo sem atrasar nem modificar o motor real escolhido pelo usuário.

# 3. Objetivo
Criar `tools/lib/runtime/shadow.js` com a função `interceptShadowRequest({ prompt, slug, actualEngine, correlationId })`.

# 4. Requisitos
- **RF-01:** Execução completamente desacoplada (fire-and-forget ou setImmediate) sem travar o endpoint de SSE.
- **RF-02:** Zero fallback para APIs de nuvem se o Ollama falhar.
- **RF-03:** Encaminhar dados classificados para o registrador de telemetria.
- **RNF-01:** Tratamento de qualquer exceção com captura silenciosa e log de diagnóstico, sem impactar o processo principal.

# 5. Arquitetura
Interceptor de borda posicionado entre a recepção da requisição e o log de auditoria.

# 6. Implementação Passo a Passo
1. Criar `tools/lib/runtime/shadow.js`.
2. Integrar chamada assíncrona ao `classifyTask`.
3. Direcionar o resultado para a telemetria do runtime.

# 7. Testes Pré-definidos
- Simular requisição de chat com interceptor ativado e verificar que a resposta síncrona não sofre atraso.
- Simular falha catastrófica do modelo local e verificar que a chamada principal não é interrompida.

# 8. Critérios de Aceite
- [ ] Funcionamento não bloqueante verificado.
- [ ] Logs e telemetria gerados adequadamente.
- [ ] Inexistência de chamadas automáticas para a nuvem.

# 9. Riscos
- Consumo extra de CPU/RAM em máquinas com recursos limitados: mitigado por checagem de RAM prévia.
