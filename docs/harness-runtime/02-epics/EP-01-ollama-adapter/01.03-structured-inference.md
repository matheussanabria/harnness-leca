# 1. Identificação
- **História:** 01.03 — Inferência Síncrona Estruturada com Telemetria Nativa
- **Arquivo Alvo:** `tools/lib/runtime/ollama-client.js`

# 2. Contexto
Tarefas de classificação e extração necessitam de chamadas síncronas/não-streaming ao Ollama com resposta em formato JSON estrito (`format: "json"`), capturando as métricas retornadas pela própria API (tokens de prompt, tokens gerados, duração total e tempo de carga).

# 3. Objetivo
Implementar `generateStructured({ model, prompt, system, options, signal })` retornando `{ data, raw, metrics }`.

# 4. Requisitos
- **RF-01:** Chamar `/api/generate` com `stream: false` e `format: "json"`.
- **RF-02:** Passar opções: `temperature`, `num_predict`, `num_ctx`, `keep_alive`, e flag `think: false` quando suportado.
- **RF-03:** Extrair métricas nativas do Ollama: `total_duration`, `load_duration`, `prompt_eval_count`, `prompt_eval_duration`, `eval_count`, `eval_duration`.
- **RF-04:** Validar memória livre via `hardware-profiler.js` antes de submeter requisição pesada.

# 5. Arquitetura
Método principal de inferência estruturada em `ollama-client.js`.

# 6. Implementação Passo a Passo
1. Montar payload com `stream: false` e `format: "json"`.
2. Efetuar fetch com `signal`.
3. Parsear resposta JSON e extrair bloco de métricas normalizado.

# 7. Testes Pré-definidos
- Inferência com mock retornando JSON válido e métricas.
- Inferência com erro 404 de modelo inexistente.
- Tratamento de timeout ou cancelamento por AbortSignal.

# 8. Critérios de Aceite
- [ ] Retorna objeto parseado e métricas estruturadas.
- [ ] Trata modelos não encontrados (404) e daemon inacessível.

# 9. Riscos
- Retorno de JSON corrompido: capturar via `try/catch` retornando erro de parse.
