# 1. Identificação
- **História:** 01.02 — Health Check e Descoberta Dinâmica de Modelos
- **Arquivo Alvo:** `tools/lib/runtime/ollama-client.js`

# 2. Contexto
Precisamos saber se o serviço local está ativo antes de tentar qualquer inferência e verificar se o modelo pretendido (`qwen3.5:4b` ou similar) está instalado.

# 3. Objetivo
Implementar `checkHealth()` e `listInstalledModels()` consumindo `/api/tags` com timeout de 1500ms e retorno normalizado.

# 4. Requisitos
- **RF-01:** `checkHealth()` retorna `{ ok: boolean, version?: string }`.
- **RF-02:** `listInstalledModels()` lista os modelos locais com nomes e tamanhos em MB.
- **RF-03:** `hasModel(name)` valida se o modelo solicitado está disponível localmente.

# 5. Arquitetura
Métodos assíncronos integrados a `tools/lib/runtime/ollama-client.js` com tratamento gracioso de falhas de rede.

# 6. Implementação Passo a Passo
1. Adicionar chamada a `/api/tags` com `AbortSignal.timeout(1500)`.
2. Tratar exceções de rede e retornar falso se o Ollama estiver desligado.
3. Adicionar método de conveniência `hasModel(modelName)`.

# 7. Testes Pré-definidos
- Mock de resposta HTTP 200 de `/api/tags`.
- Mock de erro de conexão (daemon desligado).

# 8. Critérios de Aceite
- [ ] Retorna status de saúde sem travar o processo.
- [ ] Lista modelos locais instalados.

# 9. Riscos
- Timeout longo bloquear outras rotinas: controlado por timeout estrito de 1.5s.
