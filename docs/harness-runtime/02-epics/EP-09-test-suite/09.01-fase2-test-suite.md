# 1. Identificação
- **História:** 09.01 — Suíte de Testes Unitários e de Integração da Fase 2
- **Arquivos Alvo:** `test/runtime-fase2.test.js`, `test/runtime-ollama-engine.test.js`, `tests/hia-local-runtime-panel.test.js`

# 2. Contexto
A Fase 2 introduz inferência local, que não pode ser testada chamando um modelo real em CI. Todos os cenários precisam de mocks determinísticos e sem rede.

# 3. Objetivo
Cobrir o contrato de extração, o serviço de extração, a delegação do HIA Router, o caminho de motor local na CLI e a renderização do painel de runtime local.

# 4. Requisitos
- **RF-01:** Nenhum teste depende de daemon Ollama real nem de internet.
- **RF-02:** A inferência é mockada por `globalThis.fetch`; o runner local é exercitado contra um daemon fake em processo separado.
- **RF-03:** Testes que exigem RAM livre suficiente para inferência local são marcados como *skipped* quando o ambiente não permite.
- **RF-04:** A renderização do painel é verificada por conteúdo gerado, com verificação de ausência de emojis.

# 5. Arquitetura
Três arquivos de teste com escopo claro: contrato e roteamento (`runtime-fase2`), motor local (`runtime-ollama-engine`) e interface (`hia-local-runtime-panel`).

# 6. Implementação Passo a Passo
1. Cobrir `validateExtraction` com payload válido e payload inválido.
2. Cobrir `extractKnowledge` com `fetch` mockado.
3. Cobrir `routeTask` para a delegação Local-First.
4. Cobrir `generateText` e `generateStructured` verificando o campo `format` enviado ao daemon.
5. Cobrir o runner e `ask({ engine: "ollama" })` com daemon fake em processo separado.
6. Cobrir o bloco de runtime local do painel HIA (métricas, payload vazio, ordenação).

# 7. Testes Pré-definidos
- `node --test test/runtime-*.test.js` — 100% aprovado, sem rede.
- `node --test tests/hia-local-runtime-panel.test.js` — 3 casos aprovados.

# 8. Critérios de Aceite
- [x] Nenhuma chamada de rede externa.
- [x] Falhas de ambiente (RAM) degradam para *skip*, nunca para falso positivo.
- [x] Cobertura dos quatro caminhos da Fase 2.

# 9. Riscos
- Testes que dependem de `spawn` podem ser lentos em máquinas carregadas; o timeout do runner é de 20 s.
