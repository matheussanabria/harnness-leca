# 1. Identificação
- **História:** 02.01 — Validador e Schema Estrito de Classificação
- **Arquivo Alvo:** `tools/lib/runtime/schema.js`

# 2. Contexto
A classificação de tarefas deve aderir a um contrato fixo e determinístico. Saídas inválidas ou com valores arbitrários não podem ser aceitas pelo runtime.

# 3. Objetivo
Criar `tools/lib/runtime/schema.js` contendo as enumerações aceitas e a função `validateClassification(data)` que retorna `{ valid: boolean, errors?: string[], value?: object }`.

# 4. Requisitos
- **RF-01:** Validar campos obrigatórios: `tipo`, `complexidade`, `modulo`, `executorSugerido`, `justificativa`.
- **RF-02:** Valores de `tipo` aceitos: `bug`, `feature`, `refactor`, `docs`, `test`.
- **RF-03:** Valores de `complexidade` aceitos: `baixa`, `media`, `alta`.
- **RF-04:** Valores de `executorSugerido` aceitos: `local_llm`, `cloud_llm`, `script`, `human`.
- **RNF-01:** Módulo com menos de 100 linhas e zero dependências pesadas.

# 5. Arquitetura
Validação síncrona, pura e determinística em JavaScript puro.

# 6. Implementação Passo a Passo
1. Definir constantes dos enums válidos.
2. Implementar função de sanitização e validação de cada campo.
3. Exportar validador e valores canônicos.

# 7. Testes Pré-definidos
- Testar payload 100% válido.
- Testar payload com campo ausente.
- Testar payload com valor fora do enum (ex: `tipo: "outro"`).

# 8. Critérios de Aceite
- [ ] Validação rigorosa dos tipos e enums.
- [ ] Erros detalhados quando houver não conformidade.

# 9. Riscos
- Enum rígido rejeitar variações semânticas válidas: documentado via prompt no classificador.
