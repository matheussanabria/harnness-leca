# EP-17.09: Telemetry and run logs from JSONL to tables

## 1. Identification
- **Epic:** [EP-17](README.md)
- **Priority:** P1
- **Dependencies:** 17.01
- **Blocks:** 17.13

## 2. Context
Append-only JSONL files with no rotation: `logs/telemetry/hia-executions.jsonl` (`tools/lib/hia/telemetry.js:9,46,52`), `runtime-shadow.jsonl` (`tools/lib/runtime/telemetry.js:10,61`), `global/deploy-actions.jsonl`, `deploy-pipeline-runs.jsonl`, `deploy-health-runs.jsonl`. ADR-TEL-001 already decided telemetry belongs in the SQLite event log, with absent numbers kept as NULL instead of 0.

## 3. Objective
Telemetry and run history are queryable tables with explicit retention, written transactionally.

## 4. Requirements
**Functional**
- RF1: tables `hia_executions`, `runtime_shadow_runs`, `deploy_runs` (kind: action, pipeline, health) with nullable numeric columns; unknown stays NULL.
- RF2: writers in `tools/lib/hia/` and `tools/lib/runtime/` call a repository; when the server is down the CLI opens the database directly (short transaction, busy timeout).
- RF3: importers mark legacy rows `origin=legacy` and are idempotent by a line hash.
- RF4: retention policy per table (time and size), configurable, with an audited prune command; usage evidence follows ADR-TEL-001 rules.
- RF5: readers (HIA panel `GET /api/hia/metrics`, Central) switch to queries; no full-file re-parse per request.

**Non functional**
- Files under 300 lines; no behavior change in dashboards.

## 5. Architecture
`ui/server/db/repos/telemetry.repo.js` plus the CLI-safe `tools/lib/db-client.js` created in 17.01.

## 6. Implementation
1. Migration and repo with tests (NULL handling).
2. Switch writers behind `HARNESS_TELEMETRY_STORE=file|db`; dual-write for one release if desired.
3. Importers and reader switch; retention command.
4. File map update.

## 7. Tests
| Type | Scenario | Command or file |
|---|---|---|
| Unit | NULL preserved, not coerced to 0 | `node --test tests/telemetry-repo.test.js` |
| Integration | HIA metrics endpoint identical on both stores | `node --test tests/hia-metrics.test.js` |
| Importer | idempotent legacy import | `node --test tests/telemetry-import.test.js` |

## 8. Acceptance criteria
- [ ] `GET /api/hia/metrics` returns the same figures from the database.
- [ ] No JSONL file is appended when the flag is `db`.
- [ ] Prune command is audited and respects retention classes.

## 9. Risks
- **Compatibility:** CLI writers during server downtime; direct database access with busy timeout.
- **Security:** telemetry may include prompts; store identifiers and sizes, not text.
- **Rollback:** flag back to `file`.
