# EP-17.13: Remaining-system evaluation and closing

## 1. Identification
- **Epic:** [EP-17](README.md)
- **Priority:** P2
- **Dependencies:** all other EP-17 stories
- **Blocks:** none

## 2. Context
The user asked to evaluate migrating the whole system to SQLite after the first slices. [ADR-012](../../03-decisions/ADR-012-sqlite-sistema-de-registro.md) keeps curated memory, instructions, `context/`, Atelier source files and the multi-agent ledger on disk. This story re-checks those exclusions with data instead of assumption, and closes the epic.

## 3. Objective
A recorded, evidence-based decision for every remaining store, and a verified closing of EP-17.

## 4. Requirements
**Functional**
- RF1: re-run the persistence inventory and list every file or key still written outside the database, with the reason (stays on disk, device preference, or pending).
- RF2: evaluate with measurements: (a) coordination ledger (`state.json`, `events/`, `inbox/`, `.lock`, ADR-007) for worktree and multi-CLI use, including the 5-minute stale lock takeover; (b) typed memory (ADR-009) as a database index over files; (c) Atelier source files; (d) `instructions.md` and `context/`.
- RF3: write each outcome as an ADR (accepted or rejected) with the measured criteria: concurrency incidents, agent read cost in tokens, git diffability, and tool support.
- RF4: verify there is no `localStorage` key that is the sole holder of server-needed state; remove the shared PIN path if the flag has been off for the agreed period (needs user confirmation).
- RF5: update the index, progress file, file map and the decisions README; record evidence in each story.

**Non functional**
- No deletion of legacy files without explicit user confirmation.

## 5. Architecture
Output is documentation plus small removal changes; no new storage.

## 6. Implementation
1. Inventory re-run and diff against the 2026-11-01 baseline.
2. Measurements and ADRs per store.
3. Cleanup proposals listed for user confirmation.
4. Close the epic in the index and progress.

## 7. Tests
| Type | Scenario | Command or file |
|---|---|---|
| Static | no sole-holder `localStorage` keys | `node --test tests/storage-sole-holder.test.js` |
| Docs | map check and link validity | `node tools/mapa.js check` |
| Regression | full suite | `npm test` |

## 8. Acceptance criteria
- [ ] Every store has a recorded decision.
- [ ] Inventory diff shows no unplanned file writers.
- [ ] Index and progress show EP-17 as complete with evidence.

## 9. Risks
- **Compatibility:** CLI agents rely on file memory and the ledger; do not move them without a measured benefit.
- **Security:** leftover PIN cookie; removal needs confirmation.
- **Rollback:** none needed; documentation and optional removals.
