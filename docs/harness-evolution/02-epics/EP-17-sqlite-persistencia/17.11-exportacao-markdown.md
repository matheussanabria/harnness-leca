# EP-17.11: Markdown export and import projection

## 1. Identification
- **Epic:** [EP-17](README.md)
- **Priority:** P1
- **Dependencies:** 17.02
- **Blocks:** 17.13

## 2. Context
Chat transcripts under `projects/<slug>/chats/*.md` feed memory extraction, `redact`, `sync` and the importer of external chats (`tools/import-opencode-chats.js`, `tools/lib/chat-format.js`, golden master in `tests/golden/`). These consumers expect markdown files with frontmatter (`titulo`, `sessao`, `origem`, `inicio`, `fim`, `agente`).

## 3. Objective
The database is the source of truth; markdown files are a generated, redacted projection that keeps every existing consumer working.

## 4. Requirements
**Functional**
- RF1: `tools/lib/chat-export.js` renders a conversation to the current markdown format by calling `chat-format.js` (format changes only there).
- RF2: export runs on conversation close, on demand (`node tools/chats.js export --project <slug>`) and in `sync`; output is deterministic and idempotent (same file name from conversation id).
- RF3: external importers (OpenCode, Claude Code, Gemini, Codex) write into the database first and then export, with the `sessao` id as the dedup key.
- RF4: `extraction-state.json` hashes keep matching so unchanged chats are not re-analyzed.

**Non functional**
- Golden-master tests pass unchanged; files under 300 lines.

## 5. Architecture
Export is a pure function over repository reads; no write path from markdown back into the database except the importers.

## 6. Implementation
1. Run `npm test` to confirm the golden baseline.
2. Exporter plus determinism tests.
3. Switch importers to database-first.
4. Hook into `sync`; file map update.

## 7. Tests
| Type | Scenario | Command or file |
|---|---|---|
| Golden | exported markdown equals existing golden files | `npm test` (golden master) |
| Determinism | two exports produce identical bytes | `node --test tests/chat-export.test.js` |
| Importer | external chat imports once, exports once | `node --test tests/importers.run.test.js` |

## 8. Acceptance criteria
- [ ] `sync` produces the same markdown set as before for unchanged chats.
- [ ] No chat is analyzed twice because of the export.
- [ ] Redaction applies to exported files.

## 9. Risks
- **Compatibility:** hand-edited markdown chats; exporter never overwrites a file whose hash differs from the last export without reporting it.
- **Security:** exported files hold content; `projects/*` is already git-ignored.
- **Rollback:** disable the export step; database remains authoritative.
