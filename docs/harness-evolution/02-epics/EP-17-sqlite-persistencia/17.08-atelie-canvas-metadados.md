# EP-17.08: Atelier and Canvas metadata and history

## 1. Identification
- **Epic:** [EP-17](README.md)
- **Priority:** P1
- **Dependencies:** 17.01, 17.03
- **Blocks:** 17.13

## 2. Context
Atelier metadata (`proto.json`) and the undo/redo journal live in files per prototype (`prototype-storage.service.js:81-84,152`, `prototype-history.service.js:69-72,111-114,277-278`); several writers are non-atomic (`atelier-tools.service.js:146,193,210`, `dc-inspection-writer.service.js:128`). Scratch files are under `scratch/` (EP-15, ADR-010). Canvas boards and assets are in `services/canvas/`. Source files (`screens/*.html`, `styles/*.css`) are intentionally kept on disk (ADR-012).

## 3. Objective
Metadata, version journal and Canvas boards are transactional; source files stay editable and diffable on disk, with the database holding their hashes.

## 4. Requirements
**Functional**
- RF1: tables `prototypes`, `prototype_screens` (path, content_hash, updated_at), `prototype_versions` (journal entries with parent and action), `agent_runs` (EP-15 loop: plan, steps, status, tool calls) and `canvas_boards`, `canvas_assets`.
- RF2: writing a source file and its journal row occur in one logical unit: write temp file, rename, then commit the row; on failure the row is rolled back and the temp file removed.
- RF3: blobs stay content-addressed on disk; the journal references hashes.
- RF4: importers from `proto.json`, `journal.json`, canvas indexes; flags `HARNESS_ATELIER_STORE`, `HARNESS_CANVAS_STORE`.
- RF5: agent-run steps are recorded so a hard refresh of the Atelier resumes a running or finished run with its card state.

**Non functional**
- No change to the SSE `POST /agent-run` contract; files under 300 lines.

## 5. Architecture
`prototype.repo.js`, `prototype-history.repo.js`, `canvas.repo.js`; the file writer stays in `prototype-storage` and gains a hash step. Orphan check compares disk files with `prototype_screens`.

## 6. Implementation
1. Migrations and repos with tests; journal parity tests against the current format.
2. Switch history, then metadata, then canvas, each behind its flag.
3. Agent-run recording and resume.
4. Orphan and hash-drift check command; file map update.

## 7. Tests
| Type | Scenario | Command or file |
|---|---|---|
| Contract | undo, redo, goto, checkpoint unchanged | `node --test tests/prototype-history*.test.js` |
| Failure | crash between file write and row commit leaves no drift | `node --test tests/prototype-write-atomic.test.js` |
| Integration | refresh during an agent run resumes cards | `node --test tests/atelier-agent-run-resume.test.js` |

## 8. Acceptance criteria
- [ ] History operations behave identically on `db` and `file`.
- [ ] Hash-drift check reports zero orphans on a migrated project.
- [ ] Hard refresh during an agent run restores the run state.

## 9. Risks
- **Compatibility:** external edits to HTML by the user; drift check marks them and re-hashes on next write instead of failing.
- **Security:** uploaded Canvas assets; unchanged validation rules.
- **Rollback:** per-store flags; files remain the fallback.
