# EP-17.07: Domain stores

## 1. Identification
- **Epic:** [EP-17](README.md)
- **Priority:** P1
- **Dependencies:** 17.01, 17.05
- **Blocks:** 17.13

## 2. Context
These stores are plain JSON without locks: `scrum.json` (`project-scrum-persist.js:14,77`), `app.json`/`mcp.json` (`project.service.js:95,101`), `permissions.json` (`tools/lib/permissions.js:94`), `deploy*.json` (`deploy-config.service.js:7-8`, `deploy-authorization.service.js:8`), routines state (`tools/lib/routines.js:105`), `extraction-state.json` (`tools/lib/state.js:51`), `memory-review.json`, `groups.json`. See the [inventory](../../01-architecture/sqlite-migration-inventory.md).

## 3. Objective
Replace each JSON store with tables behind the same service interfaces, with atomic updates and audit hooks.

## 4. Requirements
**Functional**
- RF1: sub-slices, each shippable alone: (a) projects registry and config, (b) scrum (epics, stories, sprints, lanes, impediments, transitions), (c) permissions rules, (d) deploy config, pipelines, health and authorizations, (e) routines state, (f) extraction and review state, chat groups.
- RF2: each sub-slice has a migration, a repository, an importer from its file, and a flag `HARNESS_<NAME>_STORE=file|db`.
- RF3: scrum keeps its schema v2 semantics and audited transitions; transition history becomes rows, not a file array.
- RF4: services write audit rows through `ctx.audit.record` for domain events.
- RF5: CLIs in `tools/` that read these files (`jira-query`, `routines`, `permissions`) read through a small shared read API or the CLI-safe `tools/lib/db-client.js` (from 17.01), so they keep working outside the server.

**Non functional**
- One PR per sub-slice; each repository file under 300 lines.

## 5. Architecture
Repositories by aggregate in `ui/server/db/repos/`. Importers in `tools/migrate/` with dry-run output showing counts and a diff summary.

## 6. Implementation
1. Order by risk: routines and extraction state, groups, permissions, projects registry, deploy, scrum last (largest surface).
2. For each: migration, repo, tests, importer dry-run, flag switch, file map.
3. CLI read path (`tools/db.js`).

## 7. Tests
| Type | Scenario | Command or file |
|---|---|---|
| Contract | existing service tests pass on both flags | `node --test tests/scrum*.test.js tests/deploy*.test.js` |
| Concurrency | two writers on scrum story status | `node --test tests/scrum-repo.test.js` |
| Importer | dry-run counts equal real import, idempotent | `node --test tests/migrate-domain.test.js` |

## 8. Acceptance criteria
- [ ] Each sub-slice runs on `db` with its old file untouched and unwritten.
- [ ] Scrum transitions are queryable and audited.
- [ ] CLIs still work with the server stopped.

## 9. Risks
- **Compatibility:** Jira sync reads `scrum.json` shape; keep the adapter in the service layer.
- **Security:** `deploy-authorizations.json` has mode 0600 today; keep restricted access to the database file and to the authorization endpoints (RBAC).
- **Rollback:** flag per sub-slice.
