# EP-17.10: Event store and canonical sessions consolidation

## 1. Identification
- **Epic:** [EP-17](README.md)
- **Priority:** P1
- **Dependencies:** 17.01, 17.05
- **Blocks:** 17.13

## 2. Context
`projects/<slug>/coordination/events.sqlite` is per project (`event-store.js:16,69`), `user_version` 1, count-based retention (`event-retention.js:19-25`). The canonical session registry is a JSON file with a fixed `.tmp` name (`session-registry.service.js:28,69`). The orchestration `eventEngine` is in-memory (ADR-TEL-001 context).

## 3. Objective
One database, one event table and one session registry, with retention classes that can never touch audit or RBAC data.

## 4. Requirements
**Functional**
- RF1: move `events` into `harness.sqlite` keeping columns, `seq` cursor semantics per project and the idempotency index; SSE cursors stay valid through a `seq` offset mapping.
- RF2: `canonical_sessions` and `session_links` tables replace the registry JSON; scan and link endpoints unchanged.
- RF3: retention classes `operational`, `usage`, `protected`; the sweep SQL filters by class, and `protected` includes audit and RBAC (those tables are separate, so the sweep never touches them).
- RF4: importer copies each per-project `events.sqlite` into the global table; original files kept until the user confirms removal.
- RF5: bridge the in-memory orchestration engine so its events persist (ADR-TEL-002).

**Non functional**
- Insert path stays under current latency; files under 300 lines.

## 5. Architecture
`event-store.js` keeps its interface and swaps its connection source for `ui/server/db/connection.js`; migrations move into the shared runner (`007-events.js`).

## 6. Implementation
1. Migration and parity tests for idempotency and cursors.
2. Switch the store; run both stores read-compared for one session.
3. Registry migration; bridge orchestration events.
4. File map update.

## 7. Tests

## 8. Acceptance criteria
- [ ] Central lists the same sessions and events before and after.
- [ ] No per-project `events.sqlite` is written when the flag is `db`.
- [ ] Retention tests prove audit tables are untouched.

## 9. Risks
- **Compatibility:** consumers holding old `seq` cursors; mapping table keeps them valid.
- **Security:** events carry `trust`; the audit trail remains the authority for actors.
- **Rollback:** `HARNESS_EVENTS_STORE=file`; original files kept.
