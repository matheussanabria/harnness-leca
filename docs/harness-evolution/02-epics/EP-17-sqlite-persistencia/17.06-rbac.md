# EP-17.06: RBAC

## 1. Identification
- **Epic:** [EP-17](README.md)
- **Priority:** P0
- **Dependencies:** 17.04, 17.05
- **Blocks:** 17.13

## 2. Context
No roles exist. Tool permission rules live in `projects/<slug>/permissions.json` (`tools/lib/permissions.js:83,94`); deploy and workflow approvals trust a free-text actor. See [ADR-013](../../03-decisions/ADR-013-identidade-rbac-auditoria.md).

## 3. Objective
Each route and sensitive action requires a named permission; users get permissions through roles, optionally per project.

## 4. Requirements
**Functional**
- RF1: tables `roles`, `permissions` (string `resource:action`), `role_permissions`, `user_roles` (user_id, role_id, project_id nullable for global).
- RF2: seed roles `owner`, `admin`, `maintainer`, `contributor`, `viewer` and the permission catalog (`chat:write`, `scrum:write`, `atelier:write`, `deploy:trigger`, `deploy:execute`, `deploy:authorize`, `workflow:approve`, `source:write`, `users:manage`, `audit:read`, ...).
- RF3: every route declares `permission` in the route table; missing declaration denies (fail closed). A test enumerates all routes.
- RF4: `ctx.can(permission, projectId)` for in-service checks; deploy authorize and workflow approve use the authenticated actor, not a request field. Separation of duties: the user who triggers a deploy cannot authorize the same run unless the policy allows.
- RF5: admin endpoints and a Settings view to assign roles; changes are audited.
- RF6: rollout modes `off|report-only|enforce`: `report-only` writes would-be denials to the audit log without blocking.
- RF7: `permissions.json` rules migrate into `role_permissions` and per-project overrides (importer, 17.07 handles the store swap).

**Non functional**
- Permission check under 1 ms (cached per session, invalidated on role change). Files under 300 lines.

## 5. Architecture
`ui/server/auth/rbac.js`, `ui/server/db/repos/rbac.repo.js`, route table gains a `permission` field consumed by one middleware placed after authentication and before the handler.

## 6. Implementation
1. Migration `006-rbac.js`, seed, repository and tests.
2. Permission catalog doc and route annotations (batch, delegable to OpenCode).
3. Middleware in `report-only`; review the audit log for false denials for one week.
4. Switch to `enforce`; settings view for roles.
5. File map update.

## 8. Acceptance criteria
- [ ] No route is reachable without a declared permission.
- [ ] `report-only` shows zero unexpected denials before `enforce`.
- [ ] Role changes appear in the audit log with the acting user.

## 9. Risks
- **Compatibility:** agents calling local endpoints need a service identity (`actor_kind=agent`) with a scoped token; defined here.
- **Security:** privilege escalation via `users:manage`; only `owner` holds it by default.
- **Rollback:** mode `off` or `report-only`.
