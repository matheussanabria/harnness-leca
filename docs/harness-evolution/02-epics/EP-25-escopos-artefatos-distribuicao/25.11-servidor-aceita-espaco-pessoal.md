# EP-25.11: Servidor aceita o espaço pessoal no Design, no estado das telas e na lista de projetos

## 1. Identificação
- **Épico:** [EP-25](README.md)
- **Prioridade:** P1
- **Dependências:** 25.02
- **Bloqueia:** 25.12
- **Origem:** fatia A da divisão da 25.06 (o código mostrou que a SPA trata projeto como obrigatório).

## 2. Contexto
A SPA principal chama o servidor sempre com um projeto. O estado das telas (`screen-state/store.js`) validava o projeto com `slugs()`, os controladores do Design exigiam que a pasta do projeto já existisse e `/api/state` só listava projetos reais. O espaço pessoal (`_pessoal`) só existe depois do primeiro uso, então essas rotas respondiam 404 para ele.

## 3. Objetivo
O servidor responde para o espaço pessoal em tudo o que a SPA chama ao abrir uma view do Design, sem mudar nada para os projetos reais e sem listar `_pessoal` entre eles.

## 4. Requisitos
**Funcionais**
- RF1: o estado das telas de escopo projeto lê e grava para `_pessoal` (pasta `ui-state` dentro do espaço pessoal).
- RF2: `GET /api/state` devolve `personal: { slug, titulo }` ao lado de `projects`, que continua só com projetos reais.
- RF3: `GET /api/project/_pessoal` responde com os dados do espaço pessoal, criando-o no primeiro uso.
- RF4: os endpoints do Design por projeto (perfil, índice, telas, histórias e arquivos de história) tratam `_pessoal` como existente.
- RF5: `_template`, slugs reservados e desconhecidos continuam recusados com 404.

**Não funcionais**
- Sem mudança de contrato para clientes atuais (campo novo apenas).
- Arquivos até 300 linhas; mapa atualizado.

## 5. Arquitetura
Helper `ui/server/scope/scope-dir.js` (`scopeDirExists`) usado pelos controladores do Design; `acceptsScope` (25.02) no estado das telas e em `/api/project/:slug`; constante `PERSONAL_SLUG` em `/api/state`. Decisão em ADR-019.

## 6. Implementação
1. Teste que falha para cada ponto (`tests/scope-server-personal.test.js`).
2. Helper e troca nos controladores do Design.
3. Estado das telas, `/api/state` e `/api/project/:slug`.
4. Suíte completa e mapa.

## 7. Testes
| Tipo | Cenário | Comando ou arquivo |
|---|---|---|
| Integração | estado das telas para `_pessoal`, separado de um projeto | `node --test tests/scope-server-personal.test.js` |
| Integração | `/api/state`, `/api/project/_pessoal` e três endpoints do Design respondem 200 | idem |
| Regressão | slugs reservados e desconhecidos seguem em 404 | idem |

## 8. Critérios de aceite
- [ ] Todas as chamadas que a SPA faz ao abrir uma view do Design respondem 200 para `_pessoal`.
- [ ] `projects` em `/api/state` não contém `_pessoal`.
- [ ] Suíte completa verde.

## 9. Riscos
- Outros pontos que validam com `slugs()` e que a SPA só chama em telas ainda não usadas sem projeto (Scrum, deploy): ficam como estão, porque são funcionalidades de escopo projeto.
- A lista de pontos restantes deve ser conferida quando a 25.12 abrir as views no navegador.
