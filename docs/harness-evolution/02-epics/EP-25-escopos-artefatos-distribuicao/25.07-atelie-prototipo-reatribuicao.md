# EP-25.07: Ateliê sem projeto e reatribuição de protótipo

## 1. Identificação
- **Épico:** [EP-25](README.md)
- **Prioridade:** P2
- **Dependências:** 25.04, 25.06
- **Bloqueia:** nenhuma

## 2. Contexto
O protótipo é o artefato mais acoplado ao projeto: `prototype-traceability-modular.service.js`, `prototype-exporter.service.js` e `prototype-artifact-import.service.js` leem o projeto, e a rastreabilidade liga telas a histórias do Scrum. As fontes (`screens/*.html`, `styles/*.css`) ficam em disco (ADR-012). O 17.08 migra os metadados.

## 3. Objetivo
Criar protótipos no workspace pessoal, mover um protótipo entre projetos e copiá-lo, tratando explicitamente os vínculos de rastreabilidade que o projeto de origem possui.

## 4. Requisitos
**Funcionais**
- RF1: Ateliê abre e cria protótipos sem projeto (dono `_pessoal`).
- RF2: a prévia de mover lista os vínculos de rastreabilidade (histórias, telas do Scrum) que serão desfeitos, mantidos como texto ou removidos, à escolha do usuário.
- RF3: o exportador e a importação de artefatos recebem o escopo e deixam de ler o projeto ativo.
- RF4: copiar um protótipo mantém o original intacto e registra `derived_from`.
- RF5: mover deixa um registro `moved_from` e mantém o desfazer do 25.04.

**Não funcionais**
- Fidelidade do protótipo preservada: comparação visual antes e depois (`npm run visual:proto`).
- Arquivos até 300 linhas; mapa atualizado.

## 5. Arquitetura
Estende o 25.04 com um adaptador de tipo `prototype` (arquivos, hashes, vínculos). Os vínculos de rastreabilidade viram dados do adaptador e não lógica do reatribuidor. Depende de 17.08 para os metadados no banco; se ainda não estiver aceito, o adaptador trabalha sobre os arquivos atuais.

## 6. Implementação
1. Inventariar as leituras de projeto nos três serviços de protótipo.
2. Migrar para o escopo com testes de regressão.
3. Adaptador `prototype` do reatribuidor.
4. Escolha de tratamento dos vínculos na prévia.
5. Comparação visual e testes ponta a ponta.

## 7. Testes
| Tipo | Cenário | Comando ou arquivo |
|---|---|---|
| Integração | mover protótipo do projeto 2 para o 3 mantém telas | `node --test tests/prototype-reassign.test.js` |
| Integração | copiar protótipo mantém o original idêntico por hash | `node --test tests/prototype-copy.test.js` |
| Visual | antes e depois da mudança de dono | `npm run visual:proto` |

## 8. Critérios de aceite
- [ ] Protótipo movido renderiza igual ao original.
- [ ] Vínculos de rastreabilidade tratados conforme a escolha do usuário e listados na prévia.
- [ ] Exportação funciona dentro do novo dono.

## 9. Riscos
- Rastreabilidade quebrada em silêncio: a prévia é obrigatória para esse tipo.
- Risco alto de regressão visual: gate de comparação como pré-requisito de aceite.

## 10. Evidências
Preencher ao concluir: relatório de comparação visual, testes e commit.
