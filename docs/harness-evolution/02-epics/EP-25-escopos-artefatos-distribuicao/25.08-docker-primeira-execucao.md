# EP-25.08: Empacotamento Docker e primeira execução guiada

## 1. Identificação
- **Épico:** [EP-25](README.md)
- **Prioridade:** P1
- **Dependências:** 25.05, 25.09
- **Bloqueia:** nenhuma

## 2. Contexto
Hoje a instalação segue `SETUP.md` e `docs/setup/02-installation.md` (Node 22.13 ou mais, git, CLIs de agentes, hooks). Alunos e engenheiros querem algo pronto, sem montar o ambiente (ADR-020). O servidor tem host e porta configuráveis (`ui/server.js`, `ui/engine-host.js`).

## 3. Objetivo
`docker compose up` sobe o Harness com um volume persistente e abre na primeira execução guiada: detecta `git` e CLIs de agentes, pede as chaves de LLM, cria o primeiro projeto e leva ao launcher. O modo por repositório (`npm run ui`) continua funcionando.

## 4. Requisitos
**Funcionais**
- RF1: `Dockerfile` multi-stage (build das ilhas, runtime com Node) e `docker-compose.yml` com volume para `data/`, `projects/` e chaves.
- RF2: escuta em `127.0.0.1` por padrão; abrir para a rede exige variável explícita e imprime aviso sobre autenticação.
- RF3: assistente de primeira execução: verificação de pré-requisitos, entrada das chaves (BYOK), projeto inicial opcional e atalho para "Sem projeto".
- RF4: chaves guardadas fora do git, com permissão restrita; nunca exibidas nos logs.
- RF5: documentação de VPS com proxy reverso e autenticação básica.
- RF6: usuário não-root no container e imagem versionada por release.

**Não funcionais**
- Primeira execução em até 10 minutos numa máquina limpa (medido e registrado).
- Arquivos até 300 linhas; documentação de instalação em um único idioma por arquivo (regra de idioma).

## 5. Arquitetura
Camada de empacotamento na raiz (`Dockerfile`, `docker-compose.yml`, `docker/`), sem alterar o backend. O assistente é uma ilha em `ui/web/` acionada quando `data/` está vazio. Decisão em [ADR-020](../../03-decisions/ADR-020-distribuicao-aberta-e-empacotamento.md); o desktop fica fora.

## 6. Implementação
1. Dockerfile e compose, com teste de build em CI local.
2. Variáveis de ambiente e bind padrão em localhost.
3. Assistente de primeira execução (protótipo aprovado antes).
4. Guia de instalação e de VPS.
5. Medição em máquina limpa (Windows com Docker Desktop, Linux).

## 7. Testes
| Tipo | Cenário | Comando ou arquivo |
|---|---|---|
| Build | imagem constrói e sobe | `docker compose build` e `up` |
| Segurança | porta só em localhost por padrão; segredo ausente dos logs | script de verificação |
| E2E | assistente cria o primeiro projeto | `npm run e2e:web` |

## 8. Critérios de aceite
- [ ] Máquina limpa chega ao launcher em até 10 minutos.
- [ ] Reiniciar o container preserva dados e chaves.
- [ ] Nenhuma chave aparece em git, logs ou na imagem.

## 9. Riscos
- Docker no Windows exige WSL2 ou Docker Desktop: documentar e registrar quantos usuários travam, insumo do critério de promoção do desktop.
- Agentes locais (Claude Code, Codex) dentro do container precisam de login próprio: descrever o caminho no assistente.

## 10. Evidências
Preencher ao concluir: tempo medido, capturas do assistente e saída do build.
