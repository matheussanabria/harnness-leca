# 02.01: Inventário da lógica de chat duplicada

## 1. Identificação
- **Épico:** [EP-02](README.md)
- **Prioridade:** P0
- **Dependências:** Nenhuma

## 2. Contexto
Historicamente, o Harness Leca possuía três pontos de entrada independentes para interação com LLMs:
1. **Central de Conversas (`/`)**: Modal `#chatModal` carregado via `partials/dialogs-chat.html`.
2. **Vibecoding Studio (`/studio`)**: Painel lateral acoplado em `partials/studio.html`.
3. **Escritório 3D/2.5D (`/escritorio`)**: Gaveta lateral `#chatPanel` em `office.html` / `office-app.js`.

Essa dispersão causava divergências em:
- Parsing e renderização de cards de código acionáveis.
- Gerenciamento de sessões de CLI (Claude Code, Gemini, Opencode).
- Cancelamento e retomada de streaming SSE.

## 3. Mapeamento de Lógica e Divergências

| Área | Implementação | Renderizador de Mensagens | Streaming / Conexão | Sessão e Estado |
|---|---|---|---|---|
| **Central (`/`)** | `chat.js` agregador + `chat-render.js` | `chat-render.js` com suporte a `chat-code-actions.js` | `chat-stream-ui.js` + `chat-execution-store.js` | `chat-session-store.js` por `slug::chatId` |
| **Studio (`/studio`)** | `studio.js` + `studio-core.js` | Compartilhado via `chat-presentations.js` (`presentation: 'studio'`) | Compartilhado via `chat-execution-store.js` | Compartilhado |
| **Escritório 3D (`/escritorio`)** | `#chatPanel` manipulado diretamente em `office-app.js` | DOM inline legado sem botões de ação de código | Listener SSE simplificado isolado | Estado transiente não sincronizado com Central |

## 4. Decisões Arquiteturais
1. **Unificação via Window Manager e `chat-presentations.js`**:
   - O painel de chat do escritório 3D passa a ser gerenciado como uma janela do Window Manager (`station: chat`), utilizando a apresentação canônica `office` ou `main`.
2. **Modelo Universal de Dados**:
   - As mensagens e sessões são desacopladas da camada de apresentação através de `ChatMessage`, `ChatSession` e `ChatExecution`.
