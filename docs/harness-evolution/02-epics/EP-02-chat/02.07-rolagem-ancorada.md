# EP-02.07: Rolagem ancorada na última mensagem

## 1. Identificação
- **Épico:** [EP-02](README.md)
- **Prioridade:** P1
- **Dependências:** 02.01, 02.02, 02.03, 02.04, 02.05, 02.06
- **Bloqueia:** 02.08

## 2. Contexto
Durante o desenvolvimento com IA no Harness Leca, respostas longas geradas via streaming SSE (com raciocínio *thinking*, múltiplos blocos de código e comparações simultâneas) provocam constante variação na altura do container de histórico (`scrollHeight`).

Sem ancoragem de rolagem inteligente (*scroll anchoring*):
1. O usuário é forçado para o rodapé da página a cada chunk de streaming, tornando impossível rolar para cima para ler mensagens anteriores enquanto a IA continua gerando a resposta.
2. Em contrapartida, quando o usuário está no final acompanhando a geração em tempo real, a tela deve acompanhar o fluxo automaticamente sem travar.
3. Se o usuário estiver lendo trechos anteriores, um botão flutuante discreto com ícone FontAwesome (`fa-arrow-down`) deve surgir no rodapé, permitindo descer suavemente com um clique (`smooth scroll`) quando desejado.
4. Esse comportamento deve operar de forma simétrica nas três apresentações do chat: **completa** (`chatHistory`), **lateral/Studio** (`studioChatHistory`) e **compacta/mini-dock** (`miniChatHistory`).

## 3. Objetivo
Implementar o mecanismo canônico de ancoragem de rolagem e botão de retorno nas três apresentações:
1. Detectar proximidade do rodapé (`wasNearBottom < 80px`) antes de atualizar o DOM a cada renderização/chunk.
2. Ancorar e rolar automaticamente para o final somente se o usuário estiver próximo do rodapé ou em nova conversa/mensagem enviada.
3. Preservar a posição relativa de rolagem caso o usuário role para cima para ler mensagens anteriores, exibindo o botão flutuante `scrollButton`.
4. Rolar suavemente para o fim (`scrollChatToBottom(presentation)`) ao clicar no botão, ocultando-o imediatamente.
5. Garantir conformidade com zero emojis, contratos em `chat-presentations.js` e limite estrito de 250 a 300 linhas por arquivo.

## 4. Requisitos
**Funcionais**
- RF1: Detecção de ancoragem: antes de aplicar o HTML das mensagens em `renderChatHistory`, verificar se cada container (`chatHistory`, `studioChatHistory`, `miniChatHistory`) está próximo do fim (`scrollHeight - scrollTop - clientHeight < 80`).
- RF2: Rolagem seletiva: manter o scroll no rodapé (`scrollTop = scrollHeight`) apenas se `wasNearBottom` for verdadeiro ou se for estado inicial (`scrollTop === 0`). Se o usuário estiver acima, preservar sua posição de leitura.
- RF3: Botão de descer por apresentação:
  - `main`: `#chatScrollBottomBtn`
  - `studio`: `#studioChatScrollBottomBtn`
  - `mini`: `#miniChatScrollBtn`
- RF4: Interação suave de descida: `scrollChatToBottom(presentation)` deve acionar `scrollTo({ top: scrollHeight, behavior: "smooth" })` no container da apresentação e ocultar o botão.
- RF5: Compatibilidade com eventos de rolagem: `handleChatHistoryScroll(container)` deve avaliar a distância do rodapé e alternar a visibilidade do botão (`none` vs `flex`).

**Não funcionais**
- Limite estrito de 250 a 300 linhas por arquivo.
- Política estrita de zero emojis: uso exclusivo de ícones FontAwesome (`fa-solid fa-arrow-down`).
- Cobertura com testes automatizados em `tests/chat-scroll-anchoring.test.js`.

## 5. Arquitetura e Contratos
- **`chat-presentations.js`**: mapeia `scrollButton` para `main`, `studio` e `mini`.
- **`chat-render.js`**: `renderChatHistory(keepScroll)` verifica `wasNearBottom` por container e chama `handleChatHistoryScroll`.
- **`chat-ui-interaction.js`**: `handleChatHistoryScroll(container)`, `scrollChatToBottom(presentation)`, `scrollStudioChatToBottom()` e `scrollMiniChatToBottom()`.
- **`dialogs-chat.html`**, **`studio.html`** e **`dialogs-misc.html`**: botões de rolagem com classe `.chat-scroll-bottom-btn`.

## 6. Critérios de Aceite
1. O streaming SSE e a renderização de histórico não forçam scroll para baixo quando o usuário está lendo mensagens anteriores (`wasNearBottom === false`).
2. O botão de rolagem surge automaticamente quando o usuário rola para cima e desaparece ao se aproximar do rodapé.
3. O botão de rolagem no mini-dock expandido (`#miniChatScrollBtn`) opera com paridade idêntica ao modal e ao Studio.
4. O clique no botão executa rolagem suave para o fim e oculta o botão.
5. Os testes em `tests/chat-scroll-anchoring.test.js` e a suíte completa passam com 100% de sucesso.
