# EP-24.04: Tools do agente para motion

## 1. Identificação
- **Épico:** [EP-24](README.md)
- **Prioridade:** P1
- **Dependências:** 24.01, 24.02
- **Bloqueia:** nenhuma
- **Pode tocar além da lista acima:** `atelier-tools.service.js` (só o registro das tools novas), `atelier-tool-instruction.service.js` (só o parágrafo de motion) e `atelier-proto-context.service.js` (só a chamada do resumo).

## 2. Contexto
O loop do Atelier interpreta tags `<tool name=...>` (`atelier-tool-tags.service.js`) e executa `atelier_write_screen`, `atelier_patch_styles`, `atelier_ask_user` e `atelier_complete` (`atelier-tools.service.js`, 256 linhas, já perto do teto, por isso o motion fica num módulo próprio). O contexto do protótipo vai ao modelo como mapa compacto de até 300 tokens (`atelier-proto-map.service.js`).

## 3. Objetivo
Ao pedir no chat algo como "entrada em cascata dos cards, 1,2 s, ease-out", o agente escreve ou ajusta a timeline e o player mostra o resultado.

## 4. Requisitos
**Funcionais**
- RF1. `motion_write_timeline { screen, doc }` grava a timeline inteira pelo store da 24.01.
- RF2. `motion_set_keys { screen, target, keys }` substitui as keys de uma faixa (e cria a faixa se não existir); `motion_remove_track { screen, target }` remove uma faixa.
- RF3. Erros de validação voltam ao modelo como resultado da tool (com faixa, keyframe e prop), para ele corrigir no turno seguinte, e nada é gravado.
- RF4. O contexto do agente ganha um resumo da timeline da tela ativa: duração, fps e uma linha por faixa (`p12 opacity,transform 0-600ms`), com teto de 200 tokens e hash de conteúdo, no mesmo esquema do proto map.
- RF5. O texto de instrução explica o formato, a lista de props permitidas e que o alvo é sempre um `data-pid` presente no mapa.
- RF6. Depois de gravar, o player recebe `HARNESS_MOTION_LOAD` (via evento do loop) sem recarregar a página.
- RF7. `tools/motion-probe.js` roda N pedidos de referência (entrada, cascata, loop de destaque, saída) contra os motores configurados e reporta a taxa de timelines válidas na primeira tentativa e depois de uma correção.

**Não funcionais**
- Até 250 linhas por arquivo; `atelier-tools.service.js` não cresce mais que o registro.
- As tools passam pelo mesmo guard do `atelier_write_screen` (rejeita tags vazadas).

## 5. Arquitetura
`motion-tools.service.js` (execução das três tools usando `motion-store`) e `motion-context.service.js` (resumo puro). O registro em `atelier-tools.service.js` só mapeia nome para handler.

## 6. Implementação
1. Resumo de contexto puro com teste de orçamento de tokens.
2. Handlers das tools com erro estruturado.
3. Registro, instrução e evento para o player.
4. Sonda com modelos reais e relatório em `docs/harness-evolution/05-progress/`.
5. Linhas no mapa (`docs/mapa/backend/atelier/atelier-tools.md`).
