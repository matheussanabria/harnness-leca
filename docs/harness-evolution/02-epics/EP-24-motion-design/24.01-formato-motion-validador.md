# EP-24.01: Formato motion@1, validador e armazenamento

## 1. Identificação
- **Épico:** [EP-24](README.md)
- **Prioridade:** P1
- **Dependências:** nenhuma
- **Bloqueia:** 24.02, 24.04

## 2. Contexto
O Atelier guarda as telas em `screens/<screen-id>.html` dentro de cada protótipo, e o sanitizer injeta `data-pid` em todo elemento (`prototype-sanitizer.service.js`). Não existe nenhum arquivo que descreva tempo. O [ADR-018](../../03-decisions/ADR-018-motion-timeline-format.md) define o formato `motion@1`.

## 3. Objetivo
O servidor lê, valida e grava a timeline de uma tela. Uma timeline inválida nunca chega ao disco, e a resposta diz exatamente o que está errado.

## 4. Requisitos
**Funcionais**
- RF1. `validateMotion(doc, { pids })` é uma função pura que devolve `{ ok, errors[], warnings[] }` e aplica as regras do ADR-018: `schema`, `duration` até 60000, `fps` em {24, 30, 60}, até 200 faixas, `t` crescente dentro de `[0, duration]`, props da lista permitida e `ease` válido.
- RF2. Uma faixa cujo `target` não existe em `pids` vira `warning` (`orphan_track`), e não erro, para que editar a tela não quebre a timeline.
- RF3. `motion-store` lê e grava `screens/<screen-id>.motion.json` com escrita atômica (arquivo temporário seguido de rename) e checagem de `rev` (hash do conteúdo) para evitar sobrescrita concorrente.
- RF4. Os endpoints `GET` e `PUT /api/project/:slug/design/prototypes/:protoId/motion/:screenId` usam o store. O `PUT` com documento inválido responde 422 com a lista de erros.
- RF5. Arquivo acima de 64 KB responde 413.

**Não funcionais**
- Cada arquivo com até 250 linhas; o validador não faz I/O.
- Ícones só FontAwesome, sem emoji (vale para mensagens exibidas na UI).

## 5. Arquitetura
`motion-schema.service.js` (puro) ← `motion-store.service.js` (disco) ← rota registrada no `route-registry` junto das rotas de protótipo. O ID da tela passa pelo mesmo validador de ID de tela já usado (`atelier-nav-contract.service.js`), o que barra path traversal.

## 6. Implementação
1. Validador puro com tabela de props permitidas e parser de `ease` (palavras-chave mais `cubic-bezier` com 4 números).
2. Store com escrita atômica e `rev`.
3. Controller e registro de rota.
4. Linhas no mapa (`docs/mapa/backend/prototype/`).

## 7. Cenários BDD
```gherkin
Funcionalidade: Timeline motion@1

  @auto
  Cenário: CP-01 Gravar uma timeline válida
    Dado uma tela com os elementos p1 e p2
    Quando gravo uma timeline motion@1 com faixas para p1 e p2
    Então o arquivo screens/<tela>.motion.json é criado
    E a resposta traz o novo rev

  @auto
  Cenário: CP-02 Recusar prop fora da lista permitida
    Quando gravo uma faixa com a prop "left"
    Então a resposta é 422
    E o erro aponta a faixa, o keyframe e a prop "left"

  @auto
  Cenário: CP-03 Faixa órfã vira aviso
    Dado uma timeline com faixa para p9, que não existe na tela
    Quando valido a timeline
    Então ela é aceita com o aviso orphan_track para p9

  @auto
  Cenário: CP-04 Conflito de rev
    Dado que outra gravação mudou a timeline
    Quando gravo com o rev antigo
    Então a resposta é 409 e o arquivo não muda
```
