# EP-24.02: Runtime da timeline no iframe

## 1. Identificação
- **Épico:** [EP-24](README.md)
- **Prioridade:** P1
- **Dependências:** 24.01
- **Bloqueia:** 24.03, 24.04, 24.05

## 2. Contexto
O `prototype-sandbox-common.service.js` injeta scripts de bridge na tela renderizada (por exemplo `prototype-bridge-links.js` e `prototype-bridge-flags.js`), e o pai conversa com o iframe por mensagens `HARNESS_PROTO_*`. Não há nada que aplique uma timeline.

## 3. Objetivo
Quando a tela tem timeline, o iframe consegue tocar a animação, pausar e mostrar o quadro exato de qualquer instante.

## 4. Requisitos
**Funcionais**
- RF1. O render inclui a timeline como JSON inerte (`<script type="application/json" id="harness-motion">`) e o script `prototype-bridge-motion.js`, mas só quando existe `.motion.json` para a tela.
- RF2. O runtime cria um `Animation` pausado por faixa (`element.animate(keyframes, { duration, fill: "both" })`), converte `t` em `offset` e aplica `ease` por segmento.
- RF3. Mensagens aceitas: `HARNESS_MOTION_SEEK { ms }`, `HARNESS_MOTION_PLAY`, `HARNESS_MOTION_PAUSE`, `HARNESS_MOTION_LOAD { doc }` (recarrega sem reload do iframe). Mensagens enviadas: `HARNESS_MOTION_READY { duration, fps }`, `HARNESS_MOTION_TIME { ms }` (no máximo 1 por quadro de tela) e `HARNESS_MOTION_ENDED`.
- RF4. `seek` é determinístico: o mesmo `ms` produz o mesmo estado visual, e o runtime responde `HARNESS_MOTION_SEEKED { ms }` depois de `requestAnimationFrame` duplo, para a exportação saber quando capturar.
- RF5. Também expõe `window.__harnessMotion = { seek, play, pause, ready }` para uso do Playwright na 24.05; a promise `ready` espera `document.fonts.ready`.
- RF6. Faixa órfã é ignorada no runtime, sem erro.
- RF7. Tela sem timeline continua idêntica à de hoje (nenhum script novo injetado).

**Não funcionais**
- Sem biblioteca de animação externa; o runtime tem até 200 linhas.
- As mensagens só são aceitas de `window.parent` (mesma regra dos outros scripts de bridge).

## 5. Arquitetura
O script é um módulo do bridge, listado no mesmo array que os outros. Ele roda dentro do sandbox `allow-scripts` sem `allow-same-origin`, então não alcança o DOM do pai.

## 6. Implementação
1. Conversor puro `toKeyframes(track, duration)` exportado para teste.
2. Runtime com controle das animações e mensagens.
3. Injeção condicional no sandbox.
4. Linha no mapa (`docs/mapa/frontend/design/atelier.md` ou um arquivo novo `motion.md`).

## 10. Riscos
- **`transform` composto:** interpolar strings de `transform` diferentes pode gerar saltos. O validador da 24.01 pode exigir a mesma lista de funções em todos os keyframes de uma faixa.
- **Rollback:** remover o script do array do bridge.
