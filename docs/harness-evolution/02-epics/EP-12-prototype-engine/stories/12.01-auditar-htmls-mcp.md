# EP-12.01: Auditar HTMLs monoliticos, MCP e snapshots

## 1. Identificacao
- **Epico:** [EP-12](../README.md)
- **Prioridade:** P0
- **Dependencias:** nenhuma
- **Bloqueia:** 12.02, 12.03, 12.05

## 2. Contexto
Atualmente, o projeto `saude-dispensacao` possui arquivos de Design System e prototipo em formatos extensos e acoplados (`projects/saude-dispensacao/design/dis-design-system.html` com mais de 1MB e `dis-fluxo-paciente/Main.dc.html` com dezenas de kilobytes). Precisamos auditar exatamente como componentes, tokens, regras de composicao e dependencias estao estruturados, alem de mapear como as ferramentas do MCP (`tools/lib/project-mcp.js`) e servicos de contexto de design interagem com esses dados.

## 3. Objetivo
Compreender como os componentes estao armazenados, extraidos e disponibilizados aos agentes, identificando as limitacoes dos scripts de extracao atuais e quais implementacoes (Vanilla, Angular, React) existem versus quais precisam ser geradas.

## 4. Requisitos
**Funcionais**
- RF1: Inventariar todos os componentes declarados no `dis-design-system.html`.
- RF2: Auditar os scripts de extracao existentes e a geracao de snapshots do Design System.
- RF3: Avaliar as ferramentas MCP disponiveis para consulta e geracao de componentes.
- RF4: Mapear quais dependencias externas (CSS/JS, fontes, icones) cada componente requer.

**Nao funcionais**
- Arquivos de codigo e relatorios com limite estrito de tamanho (< 300 linhas).
- Proibicao estrita de emojis na interface e documentacao; uso exclusivo de FontAwesome.
- Tratamento estritamente read-only dos arquivos legados originais.

## 5. Arquitetura
A auditoria mapeara os pontos de entrada do extrator semantico e do servidor MCP:
- `projects/saude-dispensacao/design/dis-design-system.html`
- `ui/server/services/project-design-context.service.js`
- `tools/lib/project-mcp.js`

## 6. Implementacao
1. Inspecionar o DOM e estruturas de marcacao de `dis-design-system.html`.
2. Mapear o funcionamento do servico de contexto de design e extracao de perfis.
3. Analisar os schemas gerados e armazenados em cache ou JSON.
4. Mapear as chamadas MCP e respostas devolvidas para agentes de IA.
5. Consolidar o relatorio de auditoria com inventario completo.

## 7. Testes
| Tipo | Cenario | Comando ou arquivo |
|---|---|---|
| Inspecao | Validar leitura sem falhas do HTML do Design System | `node -e "require('fs').readFileSync('projects/saude-dispensacao/design/dis-design-system.html')"` |
| Integracao | Executar consulta de contexto de design via servico | `node --test tests/design-routes.test.js` |

## 8. Criterios de aceite
- [x] Inventario completo de componentes e telas com classes e estilos necessarios catalogados (32 componentes mapeados).
- [x] Mapeamento das ferramentas MCP de design atuais com parametros de entrada e saida documentados.
- [x] Confirmacao de que um componente completo pode ser recuperado com todas as dependencias necessarias para renderizacao isolada.

## 9. Riscos
- **Compatibilidade:** Falta de marcadores semanticos uniformes nos HTMLs legados.
- **Segurança:** Nenhum script nao confiavel deve ser executado no processo de inspecao estatica.
- **Rollback:** Operacao estritamente de leitura, sem risco aos artefatos existentes.

## 10. Evidencias
Preenchido em 2026-10-19:
- Arquivos inspecionados: `dis-design-system.html`, `Main.dc.html`, `support.js`.
- Bundle auditado: 32 componentes mapeados no namespace `window.DS`.
- Relatorio consolidado em: [F0-audit-results.md](../reports/F0-audit-results.md).
