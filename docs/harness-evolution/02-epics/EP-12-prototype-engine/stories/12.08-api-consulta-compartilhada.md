# EP-12.08: Criar API de consulta compartilhada

## 1. Identificacao
- **Epico:** [EP-12](../README.md)
- **Prioridade:** P0
- **Dependencias:** 12.05, 12.07
- **Bloqueia:** 12.11, 12.21, 12.29

## 2. Contexto
O Atelie, o Studio e os agentes atraves do MCP precisam consultar componentes de forma dinamica, filtrando por categoria, namespace ou framework disponivel, sem precisar carregar HTMLs gigantes de 1MB a cada interacao.

## 3. Objetivo
Disponibilizar endpoints HTTP REST e integracao com MCP para consulta e resolucao de componentes do Design System Registry.

## 4. Requisitos
**Funcionais**
- RF1: Rota `GET /api/project/:slug/design/registry` listando todos os componentes com filtros.
- RF2: Rota `GET /api/project/:slug/design/registry/:componentId` devolvendo os metadados completos de um componente.
- RF3: Rota `POST /api/project/:slug/design/registry/extract-pilot` permitindo reextrair o piloto.

**Nao funcionais**
- Controller desacoplado e enxuto (< 250 linhas).
- Compatibilidade com as politicas de permissao existentes.

## 5. Implementacao
1. Criar `ui/server/controllers/design-registry.controller.js`.
2. Registrar rotas em `ui/server/router.js`.
3. Testar via suite de testes automatizados `tests/design-registry-routes.test.js`.

## 6. Testes
| Tipo | Cenario | Comando ou arquivo |
|---|---|---|
| Integracao | Endpoints REST do Registry retornam 200 e payload valido | `node --test tests/design-registry-routes.test.js` |

## 7. Criterios de aceite
- [x] Endpoints respondem com sucesso e paginacao/filtros consistentes.
- [x] Erros 404 adequados para componentes inexistentes.

## 8. Evidencias
Preenchido em 2026-10-19:
- Controller criado: `ui/server/controllers/design-registry.controller.js` (45 linhas).
- Rotas integradas em `ui/server/router.js`.
- Teste de integracao passando com 200 e 404: `tests/design-registry-routes.test.js`.
