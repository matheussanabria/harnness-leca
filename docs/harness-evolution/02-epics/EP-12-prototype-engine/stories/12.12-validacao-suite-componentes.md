# EP-12.12: Validar suite de componentes vanilla com automacao

## 1. Identificacao
- **Epico:** [EP-12](../README.md)
- **Prioridade:** P0
- **Dependencias:** 12.10, 12.11
- **Bloqueia:** 12.13 (F3)

## 2. Contexto
Esta história fecha o **Marco M1 (Extração Confiável)** do EP-12. Precisamos atestar formalmente através de testes automatizados que os componentes extraídos do HTML gigante monólito funcionam isoladamente, possuem tokens válidos e estão prontos para compor telas semânticas.

## 3. Objetivo
Executar e validar a suíte automatizada de testes que comprova a integridade e independência funcional dos componentes vanilla (`AnnotationList`, `Accordion`, `Icon`, `Button`), homologando o Marco M1.

## 4. Requisitos
**Funcionais**
- RF1: Testar que cada componente carrega sem erros de sintaxe ou referências não declaradas.
- RF2: Validar que os tokens CSS consumidos pelos componentes existem em `tokens.css` ou `theme.css`.
- RF3: Validar a geração do HTML preview isolado para cada componente.
- RF4: Emitir o relatório do Marco M1.

**Nao funcionais**
- Testes rápidos e determinísticos com `node --test`.

## 5. Implementacao
1. Escrever `tests/marco-m1-validation.test.js`.
2. Rodar e garantir 100% de aprovação.
3. Gerar relatório de evidência do Marco M1.

## 6. Testes
| Tipo | Cenario | Comando ou arquivo |
|---|---|---|
| Suite Marco M1 | Testes unitários e de integração de toda a F1 e F2 | `node --test tests/marco-m1-validation.test.js` |

## 7. Criterios de aceite
- [x] 100% dos testes da suíte Marco M1 passam com sucesso.
- [x] Relatório de homologação registrado no épico.

## 8. Evidencias
- `tests/marco-m1-validation.test.js`: 6 asserções de alto nível aprovadas cobrindo presença no registry, teto de 250 linhas, ausência de emojis, tokens CSS mapeados, integridade do DAG e geração de preview.
- Relatório de homologação registrado em `docs/harness-evolution/02-epics/EP-12-prototype-engine/reports/M1-validation-report.md`.
