# EP-12.16: Validador de schema com JSON Schema e testes

## 1. Identificacao
- **Epico:** [EP-12](../README.md)
- **Prioridade:** P0
- **Dependencias:** 12.13, 12.14, 12.15
- **Bloqueia:** 12.17 (Fase F4)

## 2. Contexto
Para evitar que protótipos sejam corrompidos por edições manuais, agentes descalibrados ou sincronizações parciais, o servidor precisa de uma camada estrita de validação que rejeite schemas malformados antes de salvar ou renderizar.

## 3. Objetivo
Implementar o validador de schema `validatePrototypeDefinition(protoData)` com mensagens de erro claras, diagnósticos pontuais de nós inválidos e validação de integridade referencial.

## 4. Requisitos
**Funcionais**
- RF1: Validar presença e formato dos campos obrigatórios de `metadata`.
- RF2: Validar que `defaultScreenId` existe no mapa de `screens`.
- RF3: Validar que cada nó declarado possui `id`, `componentId` e que os filhos referenciados existem.
- RF4: Validar integridade dos eventos de navegação (`action.target` deve corresponder a uma tela válida).
- RF5: Retornar `{ valid: boolean, errors: string[] }` detalhado.

**Nao funcionais**
- Execução síncrona rápida (< 5ms).
- Arquivo de serviço conciso (< 250 linhas).

## 5. Implementacao
1. Criar validador em `ui/server/services/prototype-validator.service.js`.
2. Escrever suíte de testes com casos de sucesso e cenários de erro propositais.
3. Atualizar documentação e backlog.

## 6. Testes
| Tipo | Cenario | Comando ou arquivo |
|---|---|---|
| Unitario | Validação de schemas válidos, inválidos e integridade referencial | `node --test tests/prototype-validator.test.js` |

## 7. Criterios de aceite
- [x] Validador rejeita com precisão schemas malformados.
- [x] Protótipos válidos são aceitos sem falso-positivos.
- [x] 100% dos testes da suíte passando.

## 8. Evidencias
- `ui/server/services/prototype-validator.service.js`: validação profunda de metadados, consistência de IDs, nós órfãos e destinos de navegação inexistentes.
- `tests/prototype-validator.test.js`: 5 cenários com 100% de aprovação.
