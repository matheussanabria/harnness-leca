# EP-12.03: Identificar contratos e funcionalidades reutilizaveis

## 1. Identificacao
- **Epico:** [EP-12](../README.md)
- **Prioridade:** P0
- **Dependencias:** 12.01, 12.02
- **Bloqueia:** 12.05, 12.13, 12.21

## 2. Contexto
Para evitar a duplicacao de codigo e criacao de servicos redundantes, o Harness Leca ja dispoe de infraestruturas relevantes como catalogo de prototipos, resolucao de perfis de design (`design-profile-resolver.service.js`), geracao de contexto de projeto (`project-design-context.service.js`) e visualizacao de camadas. Precisamos mapear objetivamente o que reaproveitar, o que estender e o que substituir.

## 3. Objetivo
Construir a matriz de decisao tecnica dos servicos existentes, definindo o papel de cada modulo na nova arquitetura do Prototype Engine.

## 4. Requisitos
**Funcionais**
- RF1: Auditar cada servico listado e classificar em Reutilizar, Estender ou Substituir.
- RF2: Definir os contratos de interface que serao mantidos ou adaptados.
- RF3: Garantir compatibilidade retroativa com as rotas de API existentes em `ui/server/routes/`.

**Nao funcionais**
- Arquitetura limpa com responsabilidade unica por modulo.
- Limite maximo de 300 linhas por arquivo.

## 5. Matriz Alvo de Avaliacao

| Servico existente | Reutilizar | Estender | Substituir | Racional |
|---|---|---|---|---|
| Extrator MCP (`project-mcp.js`) | | Sim | | Fornece ponte para agentes; adicionar ferramentas de Registry |
| Catalogo de prototipos (`prototype-catalog.js`) | Sim | | | Ja lista pastas de prototipos e componentes com perfeicao |
| Importador de HTML (`prototype-artifact-import.service.js`) | | | Sim | Substituir pelo decompositor semantico AST da Fase F4 |
| Inspetor de camadas (`prototype-atelier-view.js`) | Sim | | | Manipulacao de arvore visual e layout responsivo mantidos |
| Renderer de preview (`prototype-renderer.service.js`) | | Sim | | Corrigir tratamento de nonce em head.html e CSP modular |

## 6. Implementacao
1. Mapear o codigo-fonte de cada servico e listar suas funcoes publicas.
2. Identificar acoplamentos ou dependencias ocultas.
3. Classificar na matriz com justificativa tecnica baseada na F0.
4. Definir plano de refatoracao nao destrutivo.

## 7. Testes
| Tipo | Cenario | Comando ou arquivo |
|---|---|---|
| Unitario | Validar suite existente de servicos de design | `node --test tests/design-*.test.js` |

## 8. Criterios de aceite
- [x] Matriz de servicos 100% preenchida com decisoes justificadas.
- [x] Especificacao dos pontos de extensao de cada modulo existente.
- [x] Nenhum servico novo proposto sem a devida justificativa de substituicao.

## 9. Riscos
- **Compatibilidade:** Quebrar chamadas legadas do Atelie ao modificar servicos existentes.
- **Rollback:** Preservar arquivos legados como fallback atraves de camadas adaptadoras.
