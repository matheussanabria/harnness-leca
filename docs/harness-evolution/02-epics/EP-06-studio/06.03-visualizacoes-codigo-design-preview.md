# EP-06.03: Visualizações Código, Design e Preview

## 1. Identificação
- **Épico:** [EP-06](README.md)
- **Prioridade:** P1
- **Dependências:** EP-06.01 (layout responsivo), EP-06.02 (chat compartilhado)
- **Bloqueia:** EP-06.04 (preservação de alterações e seleção contextual)

## 2. Contexto
O Studio já exibia o app em iframe e o modo 2 Telas, mas não oferecia alternância explícita para o Ateliê de Design nem para o código-fonte do projeto. Isso impedia usar o Studio como workspace completo: revisar a tela, inspecionar o protótipo e editar o arquivo dependiam de telas separadas.

Os módulos `studio-source.js`, `studio-source-tree.js`, `studio-source-highlight.js`, `source-workspace.service.js` e `source-workspace.controller.js` já existiam no worktree, porém sem história formal de aceite.

## 3. Objetivo
Permitir que o usuário alterne, no próprio Studio, entre Preview, Design (Ateliê), Código e 2 Telas, mantendo a preferência por projeto e carregando sob demanda o conteúdo de cada modo.

## 4. Requisitos
**Funcionais**
- RF1: Normalizar aliases (`preview`/`iframe`, `code`/`source`/`codigo`, `design`/`atelie`/`atelier`, `companion`/`2telas`).
- RF2: Alternar containers, botões do toolbar e do drawer mobile sem duplicar lógica.
- RF3: Carregar o Ateliê de Design sob demanda via `renderPrototypesWorkspace`.
- RF4: Carregar o editor de código sob demanda via `loadStudioSourceWorkspace`.
- RF5: Persistir a visualização ativa por projeto em `harness_studio_active_view_<slug>`.
- RF6: Suportar abertura programática por `setStudioModeType` e inicialização por `initStudioViews`.

**Não funcionais**
- Arquivos abaixo de 250 linhas e sem misturar renderização, rede e regra de negócio.
- Ícones apenas FontAwesome, zero emojis.
- Nenhuma regressão no layout responsivo nem no chat compartilhado do Studio.

## 5. Arquitetura
- **Gerenciador de visualizações:** `ui/public/js/modules/studio-views.js` (modos canônicos, persistência e montagem do Ateliê).
- **Fachadas:** `studio.js` e `studio-canvas.js` (`setStudioModeType`).
- **Editor de código:** `studio-source.js`, `studio-source-tree.js`, `studio-source-highlight.js`.
- **API de código:** rotas `GET /api/project/:slug/source`, `GET|POST /api/project/:slug/source/file`.
- **Design:** `design-prototypes.js` renderizado dentro de `#studioDesignWorkspace`.

## 6. Implementação
1. Definir `STUDIO_VIEW_MODES` e normalização de aliases.
2. Alternar containers/controles e persistir a preferência por projeto.
3. Montar o Ateliê de Design sob demanda e reaproveitar o workspace existente.
4. Montar o editor de código sob demanda com árvore de arquivos, realce e editor.
5. Criar a suíte `tests/studio-views.test.js` para os contratos puros de alternância.

## 7. Testes
| Tipo | Cenário | Comando ou arquivo |
|---|---|---|
| Unitário | Aliases e modos canônicos | `node --test tests/studio-views.test.js` |
| Unitário | Alternância e persistência por projeto | `node --test tests/studio-views.test.js` |
| Unitário | Listagem, leitura e gravação de arquivos | `node --test tests/source-workspace.test.js` |
| Unitário | Realce e árvore de diretórios | `node --test tests/source-editor-ui.test.js` |
| Regressão | Suíte global | `npm test` e `npm run check` |

## 8. Critérios de aceite
- [x] Os quatro modos do Studio são reconhecidos por aliases e por nome canônico.
- [x] A alternância atualiza containers, toolbar e drawer mobile.
- [x] Design e Código carregam sob demanda, sem bloquear a abertura do Studio.
- [x] A preferência é persistida de forma isolada por projeto.
- [x] Testes dedicados e `npm run check` passam.

## 9. Riscos
- **Compatibilidade:** Modos antigos (`iframe` e `companion`) continuam aceitos por alias.
- **Segurança:** O editor usa as rotas existentes de source workspace, com bloqueio de travessia e segredos.
- **Rollback:** Reversão atômica de `studio-views.js` e dos módulos de código.

## 10. Evidências
- **Arquivos principais:** `studio-views.js`, `studio-source.js`, `studio-source-tree.js`, `studio-source-highlight.js`, `source-workspace.service.js`, `source-workspace.controller.js`.
- **Comandos executados e resultado:** `node --test tests/studio-views.test.js` (3/3), `tests/source-workspace.test.js` (4/4) e `tests/source-editor-ui.test.js` (2/2) aprovados; `npm run check` verde em 524 JavaScript e 15 JSON.
- **Suíte integral:** 610/611 testes aprovados; a única falha é a regressão preexistente de acentuação em `tests/engines.misc.test.js`, fora do Studio.
