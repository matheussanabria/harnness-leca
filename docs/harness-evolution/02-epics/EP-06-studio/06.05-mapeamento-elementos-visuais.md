# EP-06.05: Mapeamento de elementos visuais para arquivos e componentes

## 1. Identificação
- **Épico:** [EP-06](./README.md)
- **Prioridade:** P1
- **Dependências:** [EP-06.03](./06.03-visualizacoes-codigo-design-preview.md), [EP-06.04](./06.04-preservacao-alteracoes-selecao.md), [EP-12.30](../EP-12-prototype-engine/stories/12.30-rastreabilidade-end-to-end.md)
- **Bloqueia:** nenhuma

## 2. Contexto
O Prototype Engine já resolve o grafo Tela → Nó → Componente → Código em `ui/server/services/prototype-traceability.service.js` (EP-12.30), mas o serviço não tinha rota HTTP e nenhum consumidor no Studio. No Ateliê, `handleBridgeMessage` guarda `selectedNode` e renderiza apenas o formulário de edição em `#atelierNodeDetails` (`ui/public/js/modules/prototype-atelier.js`). O chat do Studio aceita `<contexto-elemento>` com `node-id`, `componente` e `seletor` (`ui/public/js/modules/studio-chat.js`), porém nunca recebia o arquivo de origem nem os arquivos de implementação do componente. O usuário via o elemento na tela, mas não sabia em qual arquivo ele mora.

## 3. Objetivo
Ao selecionar um elemento no preview do Ateliê, o Studio mostra o arquivo da tela, o componente do Design System, os arquivos de implementação por framework e o código gerado, e permite enviar esse mapeamento ao chat em um clique. Quando não houver componente registrado, o mapeamento aponta explicitamente o fallback de HTML nativo.

## 4. Requisitos
**Funcionais**
- RF1: expor `GET /api/project/:slug/design/prototypes/:protoId/traceability` com `screenId` e `nodeId` obrigatórios.
- RF2: o serviço de rastreabilidade devolve `files.screen`, `files.style`, `files.components` (por framework), `files.manifest` e `files.registry`, além do grafo já existente.
- RF3: o módulo `prototype-element-map.js` normaliza a resposta em `{ nodeId, screenId, componentId, screenFile, styleFile, componentFiles, code }`.
- RF4: o painel `#atelierElementMap` renderiza componente, arquivos e quantidade de frameworks gerados após cada seleção.
- RF5: o botão "Enviar para o chat" injeta `<contexto-elemento>` com `arquivo`, `componente` e `seletor`.
- RF6: falhas de rede ou nó inexistente aparecem no painel sem quebrar a edição existente.

**Não funcionais**
- Arquivos com no máximo 250 a 300 linhas; controller de rastreabilidade separado para não inflar `prototype.controller.js`.
- Ícones apenas FontAwesome; zero emojis.
- Nenhuma chamada ao endpoint fora da seleção de nó; sem polling.

## 5. Arquitetura
```
[prototype-atelier.js] ──select──> [prototype-element-map.js] ──fetch──> [API traceability]
        │                                   │                              │
        └── #atelierNodeDetails              └── insertStudioContext  [prototype-traceability.service.js]
                                                       │
                                              [studio-chat.js]
```

## 6. Implementação
1. Estender `resolveNodeTraceability` com arquivos de tela, estilo, componente e fonte do registry.
2. Criar `prototype-traceability.controller.js` e registrar a rota no `router.js`.
3. Criar `prototype-element-map.js` com busca, normalização, render e envio ao chat.
4. Adicionar `#atelierElementMap` ao layout do Ateliê e chamar o módulo em `HARNESS_PROTO_SELECT`.
5. Estender `formatContextBlock("element")` para aceitar `arquivo`.
6. Publicar `14-prototype-element-map.css` e cobrir tudo em `tests/prototype-element-map.test.js`.

## 8. Critérios de aceite
- [x] A rota de rastreabilidade responde 200 com o grafo completo e 400/404 com erro claro.
- [x] O serviço devolve arquivos de tela, estilo, componente e fonte do registry.
- [x] O painel do Ateliê lista componente, arquivos e frameworks sem quebrar a edição.
- [x] O chat recebe `arquivo`, `componente`, `seletor` e `node-id` no bloco de elemento.
- [x] Nós sem componente registrado caem em `html.element` e exibem o fallback.
- [x] Nenhum arquivo novo ultrapassa 300 linhas e não há emojis.

## 9. Riscos
- **Compatibilidade:** o formato de resposta acrescenta campos; `resolveNodeTraceability` mantém todos os campos anteriores.
- **Segurança:** a rota é somente leitura, valida `nodeId` e usa o mesmo controle de PIN/loopback do roteador.
- **Rollback:** remover a rota, o painel e o `@import` do CSS devolve o Ateliê ao estado anterior.
