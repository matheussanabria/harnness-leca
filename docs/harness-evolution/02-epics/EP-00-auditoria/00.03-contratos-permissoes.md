# 00.03: Contratos compartilhados e permissões

## 1. Identificação
- **Épico:** [EP-00](README.md)
- **Prioridade:** P0
- **Dependências:** 00.01
- **Bloqueia:** 01.01 (contrato de janela), 02.02 (modelo de chat), 08.01 (capacidades)
- **Tipo:** somente leitura.

## 2. Contexto
Cada módulo define seus formatos. Já existem pontos de contrato:
- Tipos em `ui/public/js/types/` (por exemplo `office.d.ts`, 80 linhas) e checagem com `npm run types`.
- Interface de motor `{ id, stream, status }` em `tools/lib/engines/index.js`.
- Contrato de eventos da orquestração em `ui/server/services/orchestration/`.
- Permissões: `permissions.controller.js` com `apiPermissionRequest`, `apiPermissionAnswer`, `apiProjectPermissionsGet`, `apiProjectPermissionsRemove`.
- Acesso remoto com PIN em `ui/server/config.js` e `remote.controller.js`.

## 3. Objetivo
Saber quais formatos de dados já são compartilhados, onde estão duplicados e quais operações exigem permissão, antes de criar o contrato do Window Manager.

## 4. Requisitos
**Funcionais**
- RF1: listar cada tipo declarado em `types/*.d.ts` e JSDoc `@typedef`, com onde é usado.
- RF2: identificar entidades com mais de uma forma (projeto, conversa, mensagem, história, agente, execução), comparando campos.
- RF3: listar formatos persistidos em disco (`scrum.json`, `memory.md`, `chats/*.md`, `global/*.json`) e se têm campo de versão.
- RF4: mapear o fluxo de permissões: quem pede, quem responde, onde é guardada a resposta, o que é bloqueado sem ela.
- RF5: listar rotas que alteram estado (POST, PUT, DELETE) e qual proteção cada uma tem (PIN, permissão, nenhuma).

**Não funcionais**
- Cada afirmação cita `arquivo:linha`.
- Não propor contratos novos aqui; só registrar o existente e as divergências.

## 5. Arquitetura
Não se aplica.

## 6. Implementação (roteiro de investigação)
**Passo 1. Tipos declarados**
```powershell
Get-ChildItem ui/public/js/types -File
git grep -n -E "@typedef|@callback|interface |type .* =" -- ui/public/js/types tools/lib ui/server
```

**Passo 2. Entidades duplicadas**
Para cada entidade do RF2, buscar onde é criada ou normalizada:
```powershell
git grep -n -E "function (normalize|sanitize|create|to)[A-Z]\w*(Story|Chat|Turn|Message|Project|Agent|Run)" -- ui tools
```

**Passo 3. Formatos em disco**
```powershell
git grep -n -E "version|schemaVersion" -- ui/server/services tools/lib
```

**Passo 4. Permissões**
Ler `ui/server/controllers/permissions.controller.js` e o serviço que ele chama. Seguir até a UI:
```powershell
git grep -n -E "permission" -- ui/public/js ui/server
```

**Passo 5. Rotas que alteram estado**
Usar a tabela de rotas da 00.01 e, para cada método diferente de GET, verificar o handler e o despachante do roteador quanto a PIN ou permissão.
```powershell
git grep -n -E "PIN|isAuthorized|checkPin|sendPinLoginPage" -- ui/server
```

**Passo 6. Escrever a saída** em `docs/harness-evolution/01-architecture/audit/contracts.md`.
