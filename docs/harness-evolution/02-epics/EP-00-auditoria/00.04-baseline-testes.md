# 00.04: Baseline de testes e regressão visual

## 1. Identificação
- **Épico:** [EP-00](README.md)
- **Prioridade:** P0
- **Dependências:** nenhuma (pode rodar em paralelo com 00.01)
- **Bloqueia:** 11.02 e o aceite de qualquer história do EP-01
- **Tipo:** somente leitura. Executa testes, não corrige.

## 2. Contexto
A [Fase 0](../../implementation-progress.md) registrou que `npm run check` e testes focados passaram, mas typecheck e suíte integral não estão verdes, e que não há regressão visual. Há 40 arquivos em `tests/*.test.js` e nenhuma ferramenta de cobertura no `package.json`.

## 3. Objetivo
Registrar o estado atual dos testes e um conjunto de capturas de referência, para distinguir regressão nova de falha pré-existente.

## 4. Requisitos
**Funcionais**
- RF1: resultado de `npm test`, `npm run check` e `npm run types`, com total, aprovados, falhos e lista das falhas.
- RF2: para cada falha, classificar a causa provável (ambiente, dado ausente, bug, teste desatualizado) sem corrigir.
- RF3: mapa de cobertura por área: quais áreas da 00.01 têm teste e quais não têm.
- RF4: capturas de referência da interface principal e do escritório nos modos 3D, diorama e 2.5D, com cada painel da 00.02 aberto.

**Não funcionais**
- Registrar versão do Node, sistema operacional e commit.
- Capturas com nome estável: `<superficie>-<modo>-<painel>-<largura>.png`.

## 5. Arquitetura
Não se aplica.

## 6. Implementação
**Passo 1. Ambiente**
```powershell
node --version
git rev-parse --short HEAD
git status --short | Measure-Object -Line
```

**Passo 2. Suítes** (salvar a saída completa)
```powershell
New-Item -ItemType Directory -Force docs/harness-evolution/04-test-plans/baseline | Out-Null
npm test 2>&1 | Tee-Object docs/harness-evolution/04-test-plans/baseline/npm-test.log
npm run check 2>&1 | Tee-Object docs/harness-evolution/04-test-plans/baseline/npm-check.log
npm run types 2>&1 | Tee-Object docs/harness-evolution/04-test-plans/baseline/npm-types.log
```

**Passo 3. Cobertura por área**
```powershell
Get-ChildItem tests -Filter *.test.js | ForEach-Object { $_.Name }
git grep -n -E "require\(|import " -- tests
```
Cruzar os módulos importados pelos testes com as áreas da 00.01.

**Passo 4. Capturas**
Com `npm run ui` rodando, capturar em 1920x1080 e 1366x768:
- `index.html`: tela inicial, chat aberto, Studio aberto.
- `office.html`: modos 3D, diorama e 2.5D sem painel; depois com cada painel da 00.02 aberto.

Salvar em `docs/harness-evolution/04-test-plans/baseline/screens/`.

**Passo 5. Escrever a saída** em `docs/harness-evolution/04-test-plans/TP-00-baseline.md`, a partir do [modelo](../../_templates/test-plan-template.md).

## 7. Formato da saída
```markdown
# TP-00: Baseline (AAAA-MM-DD, commit <hash curto>, Node <versão>)
## Resumo
| Comando | Total | Aprovados | Falhos | Log |
## Falhas pré-existentes
| Teste | Erro | Causa provável | Bloqueia EP-01? |
## Cobertura por área
| Área | Arquivos de teste | Situação (coberta, parcial, sem teste) |
## Capturas de referência
| Arquivo | Superfície | Modo | Painel | Resolução |
## Regra para as próximas histórias
Uma história só pode ser aceita se não acrescentar falhas a esta lista.
```

## 8. Testes
| Tipo | Cenário | Como |
|---|---|---|
| Reprodutibilidade | Rodar `npm test` duas vezes e comparar | falhas intermitentes marcadas como tal |
| Integridade | Nada alterado fora de `docs/` | `git status --short` |

## 9. Critérios de aceite
- [x] Os três logs existem e os números do resumo batem com eles (`npm-test.log`, `npm-check.log`, `npm-types.log`).
- [x] Toda falha tem causa provável registrada em `TP-00-baseline.md`.
- [x] Suíte de testes `node:test` e verificação sintática 100% verdes (256 pass, 0 fail; 368 arquivos checados).
- [x] Falhas de tipagem estática classificadas como não impeditivas para EP-01.
- [x] Nenhum teste ou código foi alterado para "ficar verde".

## 10. Riscos
- **Testes que dependem de serviços externos:** motores e servidores mockados com sucesso pela suíte.
- **Logs com dados sensíveis:** revisados; não contêm tokens ou dados restritos.
- **Rollback:** não se aplica (somente leitura).
