# 00.01: Inventário de componentes, rotas e serviços

## 1. Identificação
- **Épico:** [EP-00](README.md)
- **Prioridade:** P0
- **Dependências:** nenhuma
- **Bloqueia:** 00.02, 00.03, 01.01
- **Tipo:** somente leitura. Nenhum arquivo fora de `docs/harness-evolution/` pode ser alterado.

## 2. Contexto
A [auditoria da Fase 0](../../01-current-state-audit.md) cobriu servidor, chat, Studio, Scrum, Mapa e orquestração em nível de área. Faltam: a lista completa de rotas, as páginas HTML secundárias, o escritório e a persistência no navegador.

Pistas já confirmadas:
- Rotas declaradas como objetos `{ method, path, handler }` em `ui/server/router.js` (a partir da linha 144). Há 87 ocorrências de `method:`; nem todas usam caminho literal `"/api/..."`, então confirmar parâmetros e prefixos.
- Páginas: `index.html`, `office.html`, `deploy.html`, `diario.html`, `overview.html` em `ui/public/`.
- 40 arquivos em `tests/*.test.js`.

## 3. Objetivo
Produzir uma tabela verificável de tudo o que a aplicação expõe e persiste, para que nenhuma história posterior precise varrer o repositório.

## 4. Requisitos
**Funcionais**
- RF1: listar todas as rotas HTTP com método, caminho, handler e controller.
- RF2: listar cada página HTML com seu script de entrada e os módulos que ela carrega.
- RF3: listar módulos de front-end por área (chat, studio, scrum, design, office, shared) com linhas e responsabilidade em uma frase.
- RF4: listar serviços do servidor e o que cada um lê ou grava em disco.
- RF5: listar todas as chaves de `localStorage` e `sessionStorage` com o arquivo que lê e o que grava.
- RF6: listar arquivos acima de 300 linhas (exceto `vendor/`).

**Não funcionais**
- Toda linha da tabela cita `arquivo:linha`.
- O que não puder ser confirmado é marcado como `não verificado`, nunca deduzido.

## 5. Arquitetura
Não se aplica. Saída é documentação.

## 6. Implementação (roteiro de investigação)
Execute na raiz do repositório, em PowerShell.

**Passo 1. Rotas**
```powershell
git grep -n "method:" -- ui/server/router.js
git grep -n -E "startsWith\(|match\(|RegExp" -- ui/server/router.js
```
Abra o trecho de despacho do roteador e confirme como rotas com parâmetro (`:slug`, prefixos) são resolvidas.

**Passo 2. Controllers e serviços**
```powershell
Get-ChildItem ui/server/controllers, ui/server/services -Recurse -File |
  ForEach-Object { "{0}`t{1}" -f $_.FullName.Replace("$PWD\",''), (Get-Content $_.FullName).Count }
git grep -n -E "writeFile|appendFile|mkdir|rename|unlink|rm\(" -- ui/server tools/lib
```

**Passo 3. Páginas e entradas**
```powershell
git grep -n -E "<script|import .* from" -- "ui/public/*.html" ui/public/js/boot.js ui/public/js/app.js ui/public/js/office-app.js
```

**Passo 4. Persistência no navegador**
```powershell
git grep -n -E "(local|session)Storage\.(get|set|remove)Item" -- ui/public/js
```

**Passo 5. Arquivos grandes**
```powershell
Get-ChildItem ui, tools, scripts -Recurse -Include *.js,*.css,*.html -File |
  Where-Object { $_.FullName -notmatch 'vendor' } |
  ForEach-Object { [pscustomobject]@{ Linhas = (Get-Content $_.FullName).Count; Arquivo = $_.FullName.Replace("$PWD\",'') } } |
  Where-Object Linhas -gt 300 | Sort-Object Linhas -Descending
```

**Passo 6. Escrever a saída** em `docs/harness-evolution/01-architecture/audit/inventory.md`, com as seções abaixo.
