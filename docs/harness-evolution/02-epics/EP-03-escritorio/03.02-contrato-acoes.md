# EP-03.02: Contrato padrão de ações dos objetos

## 1. Identificação
- **Épico:** [EP-03](./README.md)
- **Prioridade:** P1
- **Dependências:** [EP-03.01](./03.01-catalogo-objetos.md), [EP-01.02](../EP-01-janelas/01.02-adaptador-estacoes.md)
- **Bloqueia:** EP-03.03, EP-03.07

## 2. Contexto
Na implementação anterior, as ações executadas ao interagir com objetos (via tecla `E` ou clique do mouse) estavam espalhadas de forma inconsistente entre chamadas imperativas globais (`window.triggerObject(id)`), callbacks aninhados no setup 3D (`context.openAgentDossier`, `context.sitAtWorkstation`), e chamadas diretas no motor 2D. Efeitos sonoros (`playDrawerSound`, `playCoffeeSound`, `playClickSound`) eram disparados por comparações de strings manuais.

## 3. Objetivo
Criar um despachante unificado de ações (`ui/public/js/office/office-action-dispatcher.js`) que implemente um contrato padrão para os tipos de ação (`window`, `drawer`, `seat`, `screen_focus`, `custom`), gerenciando som contextual, integração com `WindowManager`, atualização do `officeState` e emissão de eventos observáveis (`dai:officeAction`), mantendo retrocompatibilidade total com `window.triggerObject`.

## 4. Requisitos
**Funcionais**
- RF1: Implementar o despachante canônico `executeOfficeAction(target, context, options)` capaz de receber um ID canônico, alias legado ou descritor do catálogo `OFFICE_OBJECT_CATALOG`.
- RF2: Suportar os 5 tipos canônicos de ação:
  1. `window`: abre ou foca o módulo associado via `windowManager.open(...)`.
  2. `drawer`: seleciona o objeto no `officeState` e abre o drawer lateral.
  3. `seat`: invoca a transição de assento do contexto 3D (`sitAtWorkstation`, `sitAtWarRoom`).
  4. `screen_focus`: comuta o foco da tela do monitor (`toggleScreenFocus`).
  5. `custom`: executa handler registrado ou emite evento CustomEvent `dai:officeAction`.
- RF3: Acoplamento sonoro automático baseado na categoria/ação (armário -> gaveta, café -> caneca, arcade -> fliperama, outros -> clique).
- RF4: Manter `window.triggerObject(id)` delegando para o despachante com retrocompatibilidade total.

**Não funcionais**
- Arquivo sob o teto estrito de 250 a 300 linhas, sem misturar renderização visual e regras de negócio.
- Ícones exclusivamente FontAwesome, estritamente zero emojis.
- 100% de cobertura com testes automatizados em `tests/office-action-dispatcher.test.js`.

## 5. Arquitetura
```
[Interaction (2D/3D Click/Key 'E')]
                 │
                 ▼
    [office-action-dispatcher.js]
                 │
  ┌──────────────┼──────────────┬──────────────┐
  ▼              ▼              ▼              ▼
[WindowManager] [OfficeState]  [AudioService] [Custom/Seat Handlers]
(open/focus)   (selectObject)  (drawer/coffee) (sit/screenFocus)
```

## 6. Implementação
1. Criado `ui/public/js/office/office-action-dispatcher.js` com o contrato dos 5 tipos de ação, resolução de áudio e customHandlers.
2. Integrado `window.triggerObject` em `ui/public/js/office-app.js` delegando para `executeOfficeAction`.
3. Atualizado `interactWith` em `ui/public/js/office-2d.js` consumindo o despachante canônico.
4. Criada suíte com 6 testes automatizados em `tests/office-action-dispatcher.test.js`.

## 8. Critérios de aceite
- [x] Todas as ações de objetos executam via contrato padrão.
- [x] Módulos com `moduleId` abrem via WindowManager sem depender de nós de DOM do drawer.
- [x] Objetos informativos abrem drawer e atualizam estado.
- [x] Efeitos sonoros contextuais tocam conforme o tipo do objeto.
- [x] 100% dos testes passam.

## 9. Riscos
- **Compatibilidade:** Totalmente mitigado através de `createLegacyTriggerObject` e delegação transparente em `window.triggerObject`.
- **Segurança:** Nenhum risco de segurança; todas as ações operam no contexto da sessão frontend.
- **Rollback:** `git checkout` dos arquivos restaura as chamadas diretas anteriores.
