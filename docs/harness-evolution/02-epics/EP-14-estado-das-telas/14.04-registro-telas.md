# EP-14.04: Registro e catálogo das 13 telas

## 1. Identificação
- **Épico:** [EP-14](README.md)
- **Prioridade:** P0
- **Dependências:** 14.01
- **Branch:** `ep14/14.04-registro-telas`

## 2. Contexto
O estado de cada tela mora em chaves de `localStorage` espalhadas (`harness_groups_*`, `harness_studio_sidebar_width`, `harness_deploy_*`, `dai_*`, `harness_chat_draft_*`) ou se perde no F5. Não existe lista única das telas.

## 3. Objetivo
Um registro declara cada tela, seu escopo e o esquema do estado.

## 4. Requisitos
- `ui/server/services/screen-state/registry.js` exporta as telas: `chats`, `studio`, `prototypes` (Ateliê), `scrum`, `layers`, `board`, `audit`, `artifacts`, `routines`, `overview`, `office`, `deploy`, `diario`.
- Cada entrada: `id`, `escopo` (`projeto` ou `global`), `campos` permitidos com tipo e limite, `migraDe` (chaves antigas do `localStorage`).
- Campos fora do esquema são descartados; tamanho máximo do estado: 64 KB.
- `docs/ui/catalogo-de-telas.md` descreve as telas e o que cada uma persiste.

## 5. Arquivos que esta história pode tocar
- ui/server/services/screen-state/registry.js
- tests/screen-registry.test.js
- docs/ui/catalogo-de-telas.md

Tocar fora desta lista exige registrar o motivo na história. Cada arquivo novo fica abaixo de 300 linhas, sem emojis (ícones FontAwesome) e com linha no `MAPA.md`.

## 6. Testes
Teste de regressão para cada comportamento novo; `npm test` verde ao final.

## 7. Critérios de aceite
- [x] Toda chave de `localStorage` do cliente aparece em `migraDe` ou numa lista de exclusões justificada.
- [x] `npm test` passa na branch `ep14/14.04-registro-telas` antes do merge.
- [x] `MAPA.md` atualizado com os arquivos novos.
