# EP-14.02: Pre-commit rápido com testes afetados

## 1. Identificação
- **Épico:** [EP-14](README.md)
- **Prioridade:** P1
- **Dependências:** nenhuma
- **Branch:** `ep14/14.02-pre-commit-rapido`

## 2. Contexto
`scripts/pre-commit.js` roda `node --test tests/*.test.js` (mais de 1000 testes, 1,5 a 2 minutos) a cada commit. Isso encareceu commits atômicos e expôs testes instáveis.

## 3. Objetivo
O pre-commit roda só o que o commit toca; a suíte completa roda no pre-push e no CI.

## 4. Requisitos
- `scripts/lib/affected-tests.js`: mapeia arquivo staged para testes por convenção de nome (`foo.js` para `tests/foo*.test.js`) e por `require`/`import` direto; arquivos sem mapa rodam um conjunto de contrato fixo.
- Commit só de `.md` ou `docs/` pula os testes sem precisar de `HARNESS_SKIP_TESTS=1`.
- `.githooks/pre-push` roda a suíte completa.
- Biome ou o `npm run check` atual só nos arquivos staged.

## 5. Arquivos que esta história pode tocar
- scripts/pre-commit.js
- scripts/lib/affected-tests.js
- .githooks/pre-push
- tests/affected-tests.test.js

Tocar fora desta lista exige registrar o motivo na história. Cada arquivo novo fica abaixo de 300 linhas, sem emojis (ícones FontAwesome) e com linha no `MAPA.md`.

## 6. Testes
Teste de regressão para cada comportamento novo; `npm test` verde ao final.

## 7. Critérios de aceite
- [ ] Commit de um módulo com um teste leva menos de 15 s; o pre-push roda tudo; `HARNESS_SKIP_TESTS=1` continua funcionando.
- [ ] `npm test` passa na branch `ep14/14.02-pre-commit-rapido` antes do merge.
- [ ] `MAPA.md` atualizado com os arquivos novos.
