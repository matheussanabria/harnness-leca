# EP-16.03: Contrato de navegacao nos prompts do gerador

## 2. Contexto
Somente o prompt opt-in de qualidade (`prototype-prompt-quality.js`) ensina `data-action="goto:<screen-id>"`. O prompt legado do chat (`RULES` em `prototype-chat-bridge.js`, ~linha 19) e a `toolInstruction` do agent loop (`atelier-engine-adapters.service.js`, ~linha 239) nao mencionam navegacao; o modelo copia o caminho `screens/<id>.html` do prompt para o `href` e o preview responde 404. O bloco de contexto (`atelier-proto-context.service.js`, regras ao fim) diz apenas que as telas devem "navegar".

## 3. Objetivo
Os tres caminhos de geracao passam a instruir o contrato de navegacao e a listar os IDs de tela validos.

## 4. Requisitos
- Criar `ui/server/services/atelier-nav-contract.service.js` (CommonJS) exportando `NAV_RULES` (texto curto em ingles) e `navScreenLine(ids)`.
  - `NAV_RULES` diz: para ir a outra tela use `<a href="#" data-action="goto:<screen-id>">`; nunca use `href` para arquivos (`screens/x.html`, `x.html`) nem `goto:` dentro de `href`; `<screen-id>` e o nome do arquivo sem `.html`; link para tela que ainda nao existe deve usar o ID que sera criado.
  - `navScreenLine(ids)` devolve `Valid screen IDs: a, b, c.` (ou `Valid screen IDs: none yet.` se vazio), sem alterar o argumento.
- `atelier-engine-adapters.service.js` (280 linhas, quase no teto): apenas importar e acrescentar `NAV_RULES` ao texto de `toolInstruction`. Mudar no maximo 4 linhas; nao adicionar logica nova nele.
- `atelier-proto-context.service.js`: incluir `NAV_RULES` e `navScreenLine` com os IDs das telas em disco nas regras do bloco de contexto (so quando ja existe alguma tela).
- `prototype-chat-bridge.js` (client, ES module, nao pode importar o servico): acrescentar a `RULES` uma linha equivalente com o mesmo contrato, em portugues.
- Nao alterar `prototype-prompt-quality.js` nem testes existentes. Se um teste existente quebrar por mudanca de texto, parar e relatar qual, em vez de editar o teste.

`node --test tests/atelier-nav-contract.test.js tests/atelier-proto-context.test.js tests/atelier-engine-adapters.test.js tests/prototype-chat-bridge.test.js`. Novo teste: `NAV_RULES` contem `data-action="goto:`; `navScreenLine` com e sem IDs; o bloco de `buildProtoContext` (fixture em diretorio temporario com duas telas) lista os dois IDs e contem o contrato; o texto de `RULES` do chat contem `goto:` (ler o arquivo com `fs` se `RULES` nao for exportado).

## 8. Criterios de aceite
Testes acima passam; nenhum arquivo passa de 300 linhas; sem emojis; o mapa tem linha para o servico novo e para o teste.
