# EP-16.01: Resolvedor puro de destinos de navegacao

## 2. Contexto
O link `href="screens/orbit.html"` gerado no prototipo `portfolio` abre 404 no preview: a rota `render/<id>` so aceita IDs de tela e a ponte (`prototype-bridge.js`) so intercepta `data-action="goto:<id>"`. Falta uma funcao unica que converta qualquer destino emitido pelo gerador em um ID de tela.

## 3. Objetivo
Criar um modulo ES puro (sem DOM, sem rede) que resolve um destino bruto para um ID de tela e diz se a tela existe.

## 4. Requisitos
- Exportar `resolveScreenTarget(target, screenIds)` retornando `{ kind, screen }`.
- `kind` e `"screen"` quando o ID existe em `screenIds`; `"planned"` quando o destino parece uma tela (formato valido) mas nao existe; `"external"` para `http(s)://`, `mailto:`, `tel:`; `"none"` para vazio, `#`, `#ancora` e `javascript:`.
- Formatos aceitos, todos devolvendo o mesmo ID: `goto:orbit`, `screens/orbit.html`, `./screens/orbit.html`, `orbit.html`, `orbit`, e qualquer um deles com `#fragmento` ou `?query` (descartados). Comparacao de ID sensivel a maiusculas; espacos nas pontas sao removidos.
- IDs validos seguem `/^[A-Za-z0-9_-]+$/`; outro formato resulta em `{ kind: "none", screen: "" }`.
- Nao ler arquivos nem alterar o argumento `screenIds`.

## 5. Arquivos que esta historia pode tocar
- ui/public/js/modules/prototype-nav-resolve.js
- tests/prototype-nav-resolve.test.js
- MAPA.md

## 6. Testes
`node --test tests/prototype-nav-resolve.test.js` (carregar o modulo com `import()` e `pathToFileURL`, como em `tests/prototype-multiselect-model.test.js`). Cobrir cada formato aceito, destino planejado, externos, vazio/ancora e ID invalido.

## 8. Criterios de aceite
- Todos os testes passam; modulo abaixo de 100 linhas; sem emojis; sem alterar outros arquivos.
