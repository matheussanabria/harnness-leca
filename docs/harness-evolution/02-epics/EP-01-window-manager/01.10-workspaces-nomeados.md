# 01.10: Workspaces nomeados (Presets de Layout por Tarefa)

## 1. Identificação
- **Épico:** [EP-01](README.md)
- **Prioridade:** P1
- **Dependências:** 01.08
- **Bloqueia:** nenhuma (Marco final do EP-01)

## 2. Contexto
Durante o dia de trabalho, o usuário transita por diferentes personas e atividades: codificação e preview visual (Vibecoding), planejamento de sprint (Scrum & Memória) ou monitoramento operacional (Datacenter & Deploy). Atualmente, a persistência (01.08) salva apenas o último layout genérico. Workspaces nomeados permitem salvar arranjos específicos de janelas e alternar instantaneamente entre presets focados.

## 3. Objetivo
Implementar o `WorkspacePresetManager` com suporte a:
1. Presets canônicos do sistema (`"default"`, `"dev"`, `"scrum"`, `"ops"`).
2. Criação, listagem, carregamento e exclusão de workspaces customizados pelo usuário.
3. Isolamento estrito por projeto no `localStorage` com controle de versão `_v: 1`.
4. Restauração suave e adaptativa com higienização pelo `LayoutPersistenceManager`.

## 4. Requisitos
**Funcionais**
- RF1: Fornecer presets canônicos integrados (`DEFAULT_WORKSPACE_PRESETS`):
  - `"dev"`: Gemini / Studio em split horizontal com chat.
  - `"scrum"`: Quadro Kanban e visualizador de memórias.
  - `"ops"`: Estação de deploy e terminal de observabilidade.
- RF2: `WorkspacePresetManager` para salvar o arranjo atual com um nome amigável (`saveWorkspace(project, name)`).
- RF3: Listar workspaces disponíveis (presets do sistema + workspaces customizados do projeto).
- RF4: Carregar um workspace aplicando o layout na `WindowStore` e respeitando limites de viewport (`loadWorkspace(project, name, viewport)`).
- RF5: Impedir exclusão de presets de fábrica do sistema e permitir exclusão de workspaces de usuário.

**Não funcionais**
- Arquivo desacoplado e enxuto (< 220 linhas).
- Zero uso de emojis; ícones exclusivamente FontAwesome.
- Suíte completa de testes unitários com `node --test`.
- Não regressão da suíte global.

## 5. Arquitetura
- **Módulos:**
  - `ui/public/js/window-manager/workspace-presets.js`: presets de fábrica e gerenciador de workspaces.
- **Contratos:**
  - `WorkspacePreset`: `{ id: string, name: string, icon: string, isSystem: boolean, layout: LayoutPayload }`
  - `WorkspacePresetManager`: `{ listWorkspaces, saveWorkspace, loadWorkspace, deleteWorkspace }`

## 8. Critérios de aceite
- [x] Presets do sistema (`dev`, `scrum`, `ops`) carregam seus respectivos módulos corretamente.
- [x] Usuário pode salvar o layout corrente como um novo workspace nomeado.
- [x] Carregar um workspace fecha janelas estranhas e abre as definidas no arranjo.
- [x] Presets de sistema não podem ser apagados acidentalmente.
- [x] 100% dos testes unitários passando.

## 9. Riscos
- **Compatibilidade:** Fallback transparente para o layout default caso o workspace nomeado seja corrompido.
- **Segurança:** Sanitização de nomes de workspace impedindo injeção de caracteres de escape.
- **Rollback:** `deleteWorkspace` limpa apenas o registro do workspace sem afetar o projeto.
