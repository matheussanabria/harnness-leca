# 01.09: Layouts responsivos e breakpoints

## 1. Identificação
- **Épico:** [EP-01](README.md)
- **Prioridade:** P1
- **Dependências:** 01.07, 01.08
- **Bloqueia:** 01.10

## 2. Contexto
Janelas flutuantes (`floating`) e layouts com múltiplas colunas funcionam bem em monitores amplos, mas tornam-se inoperantes em telas móveis (< 768px) ou tablets estreitos: o toque em alças de redimensionamento é impreciso, barras de título ocupam espaço vertical precioso e janelas acabam ocultando o conteúdo umas das outras. É necessário que o Window Manager responda deterministicamente a breakpoints de tela, adaptando apresentações e dimensões sem descartar o estado original.

## 3. Objetivo
Implementar o controlador `ResponsiveLayoutManager` e regras de breakpoint para:
1. Detectar breakpoints canônicos (`mobile` < 768px, `tablet` 768-1023px, `desktop` >= 1024px).
2. Forçar apresentação adaptativa em mobile (modo `fullscreen`/`sheet` cobrindo o viewport útil), preservando a apresentação desktop original para quando a resolução for restaurada.
3. Desativar alças de redimensionamento e cursores de arraste em mobile via CSS modular.
4. Ajustar layout da barra de tarefas para dispositivos móveis com alvos de toque adequados.

## 4. Requisitos
**Funcionais**
- RF1: Função pura `getBreakpoint(width)` mapeando para `"mobile"`, `"tablet"` ou `"desktop"`.
- RF2: Função pura `resolvePresentationForBreakpoint(presentation, breakpoint)` retornando `"fullscreen"` em mobile sem sobrescrever a preferência desktop da janela.
- RF3: Função pura `computeResponsiveBounds(bounds, breakpoint, viewport, options)` calculando limites ideais para cada dispositivo.
- RF4: Controlador reativo `ResponsiveLayoutManager` com debounce em eventos de resize (`window.onresize`), aplicando bounds adaptativos no `WindowStore`.
- RF5: Desativação visual de alças de resize e cursor de arrasto em telas móveis via `14-responsive-wm.css`.

**Não funcionais**
- Arquivos de código com estrita observância do limite anti-monólito (< 250 linhas).
- Uso exclusivo de ícones FontAwesome, zero emojis.
- Não regressão no modo 3D/2.5D nem no painel tradicional.
- Cobertura de testes unitários abrangente via `node --test`.

## 5. Arquitetura
- **Módulos:**
  - `ui/public/js/window-manager/responsive-layout.js`: funções puras de breakpoints e controlador reativo de viewport.
  - `ui/public/css/office/14-responsive-wm.css`: media queries para janelas, taskbar e ocultação de alças de resize.
- **Contratos:**
  - `Breakpoint`: `"mobile" | "tablet" | "desktop"`
  - `getBreakpoint(width)` -> `Breakpoint`
  - `resolvePresentationForBreakpoint(presentation, breakpoint)` -> `WindowPresentation`
  - `computeResponsiveBounds(bounds, breakpoint, viewport, options)` -> `WindowBounds`
  - `ResponsiveLayoutManager`: `{ attach(), detach(), getCurrentBreakpoint(), syncWindows() }`

## 6. Implementação
1. Criar `ui/public/js/window-manager/responsive-layout.js` com funções puras de resolução geométrica e controlador.
2. Criar `ui/public/css/office/14-responsive-wm.css` e importar em `office.css`.
3. Criar suíte de testes unitários `tests/responsive-layout.test.js`.
4. Registrar módulos em `MAPA.md` e validar suíte geral.

## 8. Critérios de aceite
- [x] Em viewport < 768px, janelas preenchem toda a área útil abaixo da topbar.
- [x] Alças de redimensionamento e cursor `move` são desativados em telas estreitas.
- [x] Transição de mobile para desktop restaura os limites flutuantes prévios.
- [x] 100% dos testes unitários passando e total integridade de sintaxe.

## 9. Riscos
- **Compatibilidade:** Totalmente compatível com touch events e mudanças de orientação (portrait/landscape).
- **Segurança:** Operações puramente em CSS e DOM sem scripts intrusivos.
- **Rollback:** Em desktop a experiência permanece idêntica à de 01.08.
