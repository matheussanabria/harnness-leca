# EP-01.12: Multi-window host and docking in the office

## 1. Identification
- **Epic:** [EP-01](README.md)
- **Priority:** P1
- **Dependencies:** 01.11
- **Blocks:** EP-01 pilot acceptance (three panels open at once)

## 2. Context
The EP-01 acceptance says the user opens three panels, switches focus, minimizes, restores, resizes and reloads without losing state. The office has a single `<aside id="officeDrawer">` (`office.html:286`) and `station-adapter.js` renders only the active window into it, so two windows can never be visible together. `DockingManager`, `TabGroupManager` and their CSS (`13-docking.css`, `.dock-snap-preview`, `.window-tab-bar`) are never used by client code. All nine pilot checkboxes in `piloto-estacao-gemini.md` are unchecked. DAI HQ and Datacenter, promised in the README delivery, are not covered by any story.

## 3. Objective
Several windows are visible at once, each with its own container, can be snapped to screen edges, grouped into tabs and restored after a reload.

## 4. Requirements
**Functional**
- RF1: replace the single drawer with a window host that creates one container per open window (floating, side panel or maximized) and removes it on close; the content renderers stay unchanged.
- RF2: drag a window near an edge to dock it (preview, then snap) using `DockingManager`; drag onto another window to create a tab group.
- RF3: layout persistence (from 01.11) stores and restores all open windows, their dock zones and tab groups.
- RF4: finish the pilot checklist in `piloto-estacao-gemini.md` and record the result.
- RF5: list DAI HQ and Datacenter as follow-up stories (migration to the host); do not implement them here.

**Non-functional**
- Files of up to 300 lines, FontAwesome only, no emoji, keyboard access for dock and tab actions.
- The 2.5D and 3D scenes keep working; the camera focus integration from 01.03 still applies to the active window.

## 5. Architecture
`window-host.js` owns containers and the DOM; `window-manager.js` stays the state source. `station-adapter.js` becomes a thin renderer that fills a given container. Docking state lives in `DockingManager` and is serialized by the persistence manager.

## 6. Implementation
1. Build `window-host.js` and render each window into its container behind a feature flag in `localStorage`.
2. Move station rendering to container-based calls.
3. Connect drag-end to `detectDockZone` and the snap preview.
4. Add tab groups and persistence of dock state.
5. Remove the flag and the old single-drawer path after the pilot passes.
6. Update the window manager map and the EP-01 README story table.

## 8. Acceptance criteria
- [ ] Three stations are open and visible at the same time.
- [ ] A window dragged to an edge docks with a preview; two windows can be tabbed.
- [ ] A reload restores windows, dock zones and tabs.
- [ ] All nine items of the pilot checklist are checked with evidence.
- [ ] Follow-up stories for DAI HQ and Datacenter exist in the EP-01 README.
- [ ] No regression in 2.5D or 3D; `npm test` and `npm run check` are green.

## 9. Risks
- **Compatibility:** other modules query `#officeDrawer` directly; grep and migrate them before removing the old path.
- **Security:** none beyond rendering window titles as text.
- **Rollback:** the feature flag keeps the single-drawer path until the pilot passes.
