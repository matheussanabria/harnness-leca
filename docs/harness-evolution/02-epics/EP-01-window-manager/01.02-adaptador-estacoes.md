# 01.02: Adaptador das estações existentes

## 1. Identificação
- **Épico:** [EP-01](README.md)
- **Prioridade:** P0
- **Dependências:** 01.01
- **Bloqueia:** 01.03

## 2. Contexto
No escritório virtual (`ui/public/office.html`), o clique ou proximidade de objetos interativos no cenário 3D e 2.5D abria um único painel lateral fixo (`#officeDrawer`) com lógica embutida diretamente em `office-app.js`. Não havia integração com catálogo de módulos, alternância para janelas flutuantes, minimização ou gerenciamento de múltiplas janelas ativas simultaneamente.

## 3. Objetivo
Criar o `StationAdapter` conectando os objetos das estações do escritório (`gemini_desk`, `claude_desk`, `war_screen`, etc.) à fachada do `WindowManager`, permitindo que as estações abram seus módulos registrados mantendo retrocompatibilidade visual do drawer e habilitando alternância fluida para janela flutuante (`floating`) e maximizada (`maximized`).

## 4. Requisitos
**Funcionais**
- RF1: Mapear identificadores de objetos 3D/2.5D para `moduleId`s do catálogo registrado (`gemini-chat`, `claude-chat`, `war-room`, `settings`, etc.).
- RF2: Sincronizar abertura do `WindowManager` com a visibilidade e conteúdo do container de interface do escritório.
- RF3: Suportar ações de janela: Minimizar, Maximizar/Restaurar, Flutuar/Acoplar lateralmente e Fechar.
- RF4: Oferecer suporte a ícones FontAwesome em todos os botões de ação e títulos.

**Não funcionais**
- Arquivos estritamente abaixo do limite de 250-300 linhas (`station-adapter.js` com ~125 linhas).
- Zero uso de emojis no código e interface (ícones exclusivamente FontAwesome `fa-solid`).
- Nenhuma quebra de retrocompatibilidade com o carregamento dos painéis existentes.

## 5. Arquitetura
- **Módulo:** `ui/public/js/window-manager/station-adapter.js`
- **Contratos:**
  - `OBJECT_TO_MODULE_MAP`: dicionário imutável associando chaves de objetos interativos (`gemini_desk`, `claude_desk`, `board_projects`, etc.) aos módulos registrados.
  - `StationAdapter`: classe que orquestra a comunicação bidirecional entre o `WindowManager` e o DOM do `#officeDrawer`.
  - Injeção da barra de controles `.drawer-actions` com botões de alternância flutuante/dock lateral, minimizar, maximizar e fechar.
  - Escuta reativa do `WindowManager.subscribe()` para sincronizar classes CSS (`.floating`, `.maximized`, `.hidden`) e zIndex.

## 6. Implementação
1. Criação de `ui/public/js/window-manager/station-adapter.js` (< 150 linhas).
2. Atualização de `ui/public/office.html` com folha de estilos FontAwesome e estrutura da barra de ações.
3. Atualização de `ui/public/css/office/08-drawer.css` com classes de posicionamento flutuante e dimensionamento dinâmico.
4. Conexão do `stationAdapter` em `ui/public/js/office-app.js` sem estourar limites de linhas (240 linhas).
5. Criação da suíte unitária `tests/station-adapter.test.js`.

## 8. Critérios de aceite
- [x] Objetos interativos mapeiam com precisão para módulos cadastrados no `WindowRegistry`.
- [x] O `#officeDrawer` responde a comandos de abertura e fechamento via `WindowManager`.
- [x] Alternância entre modo lateral e flutuante funciona preservando o conteúdo interno da estação.
- [x] Todos os ícones são FontAwesome (`fa-solid`).
- [x] Suíte de testes unitários dedicada passa 100% sem falhas.

## 9. Riscos
- **Compatibilidade:** Minimizado ao preservar os mesmos seletores e métodos de carregamento de conteúdo legado (`openStationDrawer`).
- **Segurança:** Sem execução de scripts externos; CSP e sanitização preservadas.
- **Rollback:** Desacoplamento modular permite retornar ao drawer estático sem tocar nos renderers 3D.
