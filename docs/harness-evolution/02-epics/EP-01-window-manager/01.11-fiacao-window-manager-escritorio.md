# EP-01.11: Wire the Window Manager facade into the office UI

## 1. Identification
- **Epic:** [EP-01](README.md), also closes the UI gaps of EP-04.02 to EP-04.05
- **Priority:** P0
- **Dependencies:** 01.05, 01.08, 01.10, 04.02 to 04.05
- **Blocks:** 01.12, and any story that adds an agent action to the office (EP-08 UI)

## 2. Context
The 2026-10-24 gap review ([epic-gaps](../../05-progress/epic-gaps.md), manually verified) found that the facade is built and unit-tested, but nothing in the office calls it:
- `windowManager.workspaces.*` (list, save, load, delete) and `windowManager.persistence.*` (save, restore, clear) have no caller outside `ui/public/js/window-manager/` (`window-manager.js:52-77`).
- `LayoutPersistenceManager` and `ResponsiveLayoutManager` are never instantiated. `14-responsive-wm.css` targets selectors that do not exist (`.dai-taskbar`, `.floating-window`, `.drawer-header-actions`) instead of `.window-taskbar`, `.office-drawer.floating` and `.drawer-actions`.
- The taskbar changes the active window, but the `windowManager.subscribe` handler in `station-adapter.js:162-206` only toggles classes. It never calls `renderDrawerContent`, so the drawer keeps the previous station's content.
- `windowManager.unsaved` is only marked and cleared by `studio-source.js`. Nothing catches `UNSAVED_CHANGES`, renders `blockers` or uses `force`. Studio still uses `window.confirm` (`studio-views.js:66,120,141`).
- `window-store.js` has 312 lines, above the 300-line cap.

## 3. Objective
From the office, the user can switch windows from the taskbar and see the right content, save and load named workspaces and system templates, find the layout restored after a reload, and is stopped by a readable dialog when a switch would lose unsaved work.

## 4. Requirements
**Functional**
- RF1: when the active window changes (taskbar, focus, restore), the drawer renders that window's station. Re-rendering is skipped when the active window id did not change.
- RF2: instantiate persistence and responsive managers once in the office bootstrap and pass them to the facade. Save on window change (debounced) and call `persistence.restore` on boot, per active project.
- RF3: add a workspace control in the office HUD: list the project's workspaces and the four templates (`development`, `planning`, `quality`, `operations`), load one, save the current layout under a name, delete a user workspace. System templates cannot be deleted.
- RF4: when `workspaces.load` or a project switch hits `UNSAVED_CHANGES`, show a dialog built from `blockers` with Save, Discard and Cancel. Discard calls the same transition with `force: true`. Replace the `window.confirm` calls in Studio with the same dialog.
- RF5: fix the selectors in `14-responsive-wm.css` to the real class names and verify mobile fullscreen, disabled drag handles and desktop bounds restore on resize.
- RF6: split `window-store.js` to 300 lines or fewer without changing its public API.

**Non-functional**
- Files of up to 300 lines; rendering, DOM and business rules in separate modules. New code goes in `ui/public/js/window-manager/` or `ui/public/js/office/`, not in `office-app.js` (keep it from growing).
- FontAwesome icons only. No emoji. No `window.confirm`, `alert` or `prompt`.
- No regression in the 2.5D or 3D offices. Persistence must tolerate corrupt or missing storage.

## 5. Architecture
```
office-app.js (bootstrap only)
  -> window-manager/wm-bootstrap.js        builds facade + persistence + responsive, returns windowManager
  -> office/workspace-menu.js              HUD control for RF3 (DOM only, calls windowManager.workspaces)
  -> shared/unsaved-dialog.js              RF4 dialog (blockers -> save/discard/cancel)
  -> window-manager/station-adapter.js     RF1: render on active-window change
```
Decision to record in `03-decisions/` if it holds for more than this story: the facade is the only entry point for UI code; modules under `window-manager/` do not read the DOM.

## 6. Implementation
Each step leaves the app working.
1. RF1: track `renderedWindowId` in `station-adapter.js`; call `renderDrawerContent` when the active id changes. Add a test with a fake `windowManager`.
2. RF6: extract helpers from `window-store.js`.
3. RF2: add `wm-bootstrap.js`, wire save and restore, keep the `office-session-storage.js` prefixes.
4. RF4: build `unsaved-dialog.js`, wire it to the project switch in `app.js:110-117` and to `workspaces.load`; replace the three Studio confirms.
5. RF3: build `workspace-menu.js` and its CSS partial; add the mount point in `office.html`.
6. RF5: correct the selectors; add the responsive test.
7. Update `docs/mapa/06-office-window-manager.md` and the `MAPA.md` index.

## 8. Acceptance criteria
- [x] Clicking a taskbar item swaps the drawer content to that station.
- [x] A saved workspace survives a reload and can be loaded and deleted from the HUD; the four templates load.
- [x] After a reload the last layout of the active project is restored.
- [x] Switching project or workspace with unsaved changes shows the dialog; Cancel keeps everything, Discard proceeds, Save saves then proceeds.
- [x] No `window.confirm` remains in `ui/public/js`.
- [ ] A mobile viewport shows the drawer fullscreen with drag handles disabled.
- [x] `window-store.js` is 300 lines or fewer; new files are within the cap and contain no emoji.
- [x] `npm test` and `npm run check` are green; screenshots pending manual validation.

## 9. Risks
- **Compatibility:** persisted layouts from the unused 01.08 format may not exist; restore must ignore unknown versions.
- **Security:** workspace names are user input; render with `textContent` and limit the length.
- **Rollback:** the bootstrap sits behind one import in `office-app.js`; removing it returns to the current behavior.
