# 01.07: Docking, abas e divisão de tela

## 1. Identificação
- **Épico:** [EP-01](README.md)
- **Prioridade:** P1
- **Dependências:** 01.06
- **Bloqueia:** nenhuma

## 2. Contexto
Com janelas flutuantes implementadas (01.06), usuários frequentemente precisam trabalhar com múltiplos contextos simultaneamente (ex: painel de chat da mesa ao lado do editor de código ou mapa do escritório). Atualmente, organizar as janelas lado a lado requer redimensionamento manual. Além disso, quando o espaço de tela é limitado, é essencial permitir o agrupamento de janelas em abas (Tabbed Groups) e o acoplamento instantâneo em zonas (metade esquerda, metade direita, tela inteira).

## 3. Objetivo
Implementar o `DockingManager` e funções de layout com suporte a:
1. Acoplamento de janelas em zonas pré-definidas (esquerda, direita, topo, rodapé, tela cheia).
2. Detecção geométrica de bordas para snapping durante arraste ou acionamento direto via controles.
3. Gerenciamento lógico de grupos de abas (`TabGroupManager`) para alternar e consolidar janelas em um contêiner compartilhado.
4. Total preservação do estado anterior ao desacoplar (`undock`).

## 4. Requisitos
**Funcionais**
- RF1: Função pura `computeDockBounds(zone, viewport, options)` para cálculo determinístico de dimensões em zonas `'left'`, `'right'`, `'top'`, `'bottom'`, `'maximize'`.
- RF2: Função pura `detectDockZone(pointer, viewport, edgeThreshold)` para detecção de intenção de acoplamento por proximidade da borda.
- RF3: `TabGroupManager` para gerenciar estado reativo de grupos de abas (criação, adição, remoção, alternância de aba ativa e destruição de grupo).
- RF4: Controles de docking integrados no cabeçalho da janela ou via API programática no `WindowManager`.
- RF5: Desacoplamento suave (`undock`), restaurando os bounds flutuantes originais da janela.

**Não funcionais**
- Arquivos estritamente abaixo do limite de 250 a 300 linhas (`docking-manager.js` < 230 linhas).
- Proibição absoluta de emojis; uso de ícones FontAwesome (`fa-solid fa-table-columns`, `fa-solid fa-clone`, etc.).
- Não regressão no modo 2.5D, na topbar nem no painel tradicional.
- Cobertura de testes unitários abrangente via `node --test`.

## 5. Arquitetura
- **Módulos:**
  - `ui/public/js/window-manager/docking-manager.js`: cálculos geométricos puros, gerenciamento de abas e acoplamento.
  - `ui/public/css/office/13-docking.css`: estilos visuais para zonas de docking, indicadores de snap e abas tabuladas.
- **Contratos:**
  - `computeDockBounds(zone, viewport, options)` -> `{ x, y, width, height }`
  - `detectDockZone(pointer, viewport, edgeThreshold)` -> `DockZone`
  - `TabGroupManager`: `{ createGroup, addTab, removeTab, setActiveTab, getGroup, destroyGroup }`
  - `DockingManager.dock(windowId, zone)` / `DockingManager.undock(windowId)`

## 6. Implementação
1. Criar `ui/public/js/window-manager/docking-manager.js` com funções puras de docking, detecção de borda e `TabGroupManager`.
2. Criar folha de estilos `ui/public/css/office/13-docking.css` para layout de docking e abas.
3. Criar suíte de testes unitários em `tests/docking.test.js`.
4. Integrar com `office.html` e registrar em `MAPA.md`.

## 8. Critérios de aceite
- [x] Zonas `'left'` e `'right'` dividem o viewport de forma responsiva respeitando topbar e taskbar.
- [x] Detecção de borda identifica intenção de dock com limiar configurável.
- [x] TabGroupManager suporta múltiplas janelas em abas e alternância instantânea.
- [x] Undock restaura exatamente as dimensões flutuantes pré-acoplamento.
- [x] Todos os testes unitários passando e conformidade com diretrizes estritas do repositório.

## 9. Riscos
- **Compatibilidade:** Totalmente agnóstico de ambiente (funciona em Node.js e navegadores modernos).
- **Segurança:** Manipulação estrita de propriedades CSS e estado em memória sem eval ou scripts dinâmicos.
- **Rollback:** Desacoplamento não destrutivo; janela pode voltar a flutuante livre ou sidebar a qualquer momento.
