# EP-11.04: Design System e inconsistências visuais

## 1. Identificação
- **Épico:** [EP-11](./README.md)
- **Prioridade:** P2
- **Dependências:** [EP-11.01](./11.01-matriz-auditoria-evidencias.md), [EP-11.02](./11.02-estados-de-teste-distintos.md) e [EP-11.03](./11.03-integracao-quadro-componentes.md)
- **Bloqueia:** 11.05 (regressão automatizada)
- **Frente:** `opencode/qualidade`

## 2. Contexto
O Harness Leca conta com tokens fundamentais (`tokens.css`, `theme.css`) e componentes declarados no Design System. No entanto, o motor de auditoria até agora só auditava requisitos de negócio e testes em código backend/frontend — deixando de fora a conformidade visual e de Design System.
Inconsistências visuais como uso de cores "hardcoded" (em vez de variáveis semânticas `--primary-interactive`, `--neutral-body`, etc.), fontes fora da escala padrão, quebras de contraste ou elementos com classes não padronizadas passam desapercebidos sem um scanner automatizado de tokens e estilos.

## 3. Objetivo
Implementar um serviço e endpoint de auditoria de consistência visual e Design System (`design-system-audit.service.js`) que analisa templates, HTMLs e folhas de estilo do projeto ou protótipos, detectando:
1. Cores hardcoded (hexadecimais, rgb/rgba) que deveriam utilizar tokens CSS.
2. Inconsistências de espaçamento e tipografia arbitrária.
3. Uso indevido de emojis em código de interface visual.
4. Ausência de tokens obrigatórios do Design System (`tokens.css` e `theme.css`).

## 4. Requisitos

**Funcionais**
- **RF1:** Analisar folhas de estilo e marcação HTML em busca de valores de cores hex/rgb inline que violem a adoção dos tokens semânticos do Design System.
- **RF2:** Verificar se o projeto possui a estrutura obrigatória do Design System (`design/ds/tokens.css` e `design/ds/theme.css`).
- **RF3:** Detectar uso de emojis proibidos em marcação HTML/CSS visual, recomendando classes FontAwesome.
- **RF4:** Classificar achados por severidade (`warning`, `error`, `info`) e categoria (`color-token`, `typography`, `spacing`, `emoji`, `missing-tokens`).
- **RF5:** Expor `GET /api/project/:slug/audit/design-system` com o resumo de conformidade (score 0-100%, total de violações e lista detalhada por arquivo/linha).
- **RF6:** Oferecer módulo de interface pura `design-audit-ds.js` para renderizar o painel de auditoria visual na aba Auditoria com FontAwesome e zero emojis.

**Não funcionais**
- Arquivos de código limitados estritamente a 300 linhas (meta < 250 linhas).
- Regras de Clean Code, funções puras testáveis sem I/O obrigatório e com injeção de dependências.
- Zero emojis no código e templates.

## 5. Arquitetura
```
[design-system-audit.service.js]
  analisa CSS / HTML -> encontra hardcoded colors, emojis, tokens ausentes
        |
[audit.controller.js] / [audit.routes.js]
  GET /api/project/:slug/audit/design-system
        |
[design-audit-ds.js]
  card/seção de Conformidade do Design System na aba Auditoria
```

## 6. Testes

| Tipo | Cenário | Comando ou arquivo |
|---|---|---|
| Unitário | Detecção de cores hardcoded vs tokens | `node --test tests/design-system-audit.test.js` |
| Unitário | Validação de tokens obrigatórios do DS | `node --test tests/design-system-audit.test.js` |
| Unitário | Detecção de emojis e recomendação FontAwesome | `node --test tests/design-system-audit.test.js` |
| Integração | Rota GET /api/project/:slug/audit/design-system | `node --test tests/design-system-audit-http.test.js` |
| Estrutural | Limite de linhas e ausência de emojis | `node scripts/check.js` |

## 8. Critérios de aceite
- [x] O scanner detecta cores hardcoded e sugere tokens equivalentes.
- [x] A ausência de `tokens.css` ou `theme.css` é apontada como não-conformidade estrutural.
- [x] O scanner detecta emojis na interface e orienta uso de FontAwesome.
- [x] O endpoint devolve o relatório estruturado com score de conformidade percentual.

## 10. Evidências
- `ui/server/services/audit/design-system-audit.service.js`: scanner e score.
- `ui/server/controllers/audit.controller.js` e `routes/audit.routes.js`: `GET /api/project/:slug/audit/design-system`.
- `ui/public/js/modules/design-audit-ds.js`: painel puro com FontAwesome.
- `node --test tests/design-system-audit.test.js`: 6/6 verdes.
