# EP-11.05: Regressão automatizada

## 1. Identificação
- **Épico:** [EP-11](./README.md)
- **Prioridade:** P2
- **Dependências:** 11.01 a 11.04
- **Frente:** `opencode/qualidade`

## 2. Contexto
O conjunto mínimo que precisa estar verde antes de commit/push existia espalhado em scripts sem teste próprio.

## 3. Objetivo
Cadeia única `scripts/regressao.js` (`npm run regressao`), que para na primeira falha:
1. `scripts/check.js` (sintaxe e JSON)
2. `node --test tests/*.test.js`
3. `tools/verify-index.js`
4. `tools/types-baseline.js` (dívida de tipos não pode crescer; baseline em `quality/types-baseline.json`)

O hook `.githooks/pre-push` executa a cadeia quando existe `quality/regression-enforced` ou `HARNESS_REGRESSION=1`.

## 4. Mudanças
- `runRegression` aceita `steps` e `runner` injetáveis (default inalterado), dividido em `defaultSteps` e `runChain`.
- Novo `tests/regressao.test.js` (3 testes).

## 5. Critérios de aceite
- [x] Cadeia ordenada com parada na primeira falha (testado)
- [x] Cadeia padrão contém as 4 etapas, terminando em types-baseline (testado)
- [x] Hook pre-push referencia `regressao.js` (testado)

## 6. Evidências
- `node --test tests/regressao.test.js`: 3/3 verdes.
- `npm run check` completo e a suíte inteira não foram executados nesta entrega (lentos).
