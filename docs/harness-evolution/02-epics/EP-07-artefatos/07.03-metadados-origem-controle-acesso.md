# EP-07.03: Metadados de origem e controle de acesso

## 1. Identificação
- **Épico:** [EP-07](./README.md)
- **Prioridade:** P1
- **Dependências:** [EP-07.02](./07.02-importacao-arquivos-pastas.md)
- **Bloqueia:** [EP-07.04](./07.04-previews-seguros.md) (previews seguros)

## 2. Contexto
A EP-07.02 passou a gravar arquivos em `projects/<slug>/artifacts/`, mas o inventário só sabe que eles vieram de `artifacts`. O nome original, a forma de envio, a data, o tamanho e o checksum não ficam registrados, e qualquer acesso remoto autenticado pelo PIN enxerga o mesmo inventário do computador local.

## 3. Objetivo
Registrar a origem de cada artefato importado e permitir que o usuário o torne visível somente no computador local. O inventário continua sem expor conteúdo de arquivo, e a alteração de acesso só pode ser feita localmente.

## 4. Requisitos
**Funcionais**
- RF1: manter um manifesto versionado em `artifacts/.metadata.json`, fora do inventário, com uma entrada por arquivo relativo.
- RF2: registrar na importação `origin: import`, `source: files|folder`, nome original, data, tamanho, MIME, SHA-256 e acesso inicial `project`.
- RF3: mesclar os metadados ao inventário e exibir a origem resumida na aba Artefatos.
- RF4: aceitar os níveis de acesso `project` e `local`; `local` só aparece para requisições de loopback e não entra no resumo remoto.
- RF5: expor `POST /api/project/:slug/artifacts/access` com JSON `{ file, access }`, somente para loopback.
- RF6: a aba Artefatos mostra o acesso e permite alternar entre projeto e somente local quando a sessão for local.
- RF7: arquivos importados antes desta história, sem entrada no manifesto, continuam visíveis como `project` e com origem não registrada; ao alterar o acesso, recebem uma entrada.
- RF8: manifesto ausente é tratado como vazio; manifesto inválido gera aviso, não derruba o inventário e bloqueia novas gravações até ser corrigido.
- RF9: falha ao registrar metadados de uma importação remove o arquivo recém-gravado, sem deixar órfão.
- RF10: nenhum conteúdo de arquivo, caminho absoluto ou segredo é devolvido pelo inventário ou pelo manifesto.

**Não funcionais**
- Arquivos de até 300 linhas, com metadados separados do controller e da renderização.
- Ícones apenas FontAwesome. Nenhum emoji.
- Escrita atômica do manifesto, sem seguir symlink e sem sair de `artifacts/`.
- Nenhuma regressão nas abas Scrum, Mapa em Camadas, Quadro, Auditoria e Protótipos.

## 5. Arquitetura
```
[artifact-import.service.js]
  grava o arquivo e remove se o metadado falhar
          |
[artifact-metadata.service.js]
  artifacts/.metadata.json (version, updatedAt, items)
          |
[artifact-inventory.service.js]
  mescla origem + acesso
  filtra "local" quando includeLocal=false
          |
[artifact.controller.js]       [artifact-access.controller.js]
  GET inventário                 POST acesso (loopback)
          |
[design-artifacts.js] + [design-artifacts-access.js]
  badge de acesso + alternância
```

Manifesto:
```json
{
  "version": 1,
  "updatedAt": "2026-10-21T12:00:00.000Z",
  "items": {
    "artifacts/docs/nota.md": {
      "origin": "import",
      "source": "folder",
      "originalName": "nota.md",
      "importedAt": "2026-10-21T12:00:00.000Z",
      "size": 128,
      "mime": "text/markdown",
      "sha256": "<64 hex>",
      "access": "project"
    }
  }
}
```

O controle de acesso vale para artefatos importados. Os demais tipos continuam `project` e serão tratados no preview seguro da 07.04.

## 6. Implementação
1. Criar o serviço de metadados com leitura tolerante, validação, escrita atômica e bloqueio de symlink.
2. Registrar metadados na importação e desfazer o arquivo se o registro falhar.
3. Mesclar metadados e filtrar `local` no inventário; expor `canManageAccess`.
4. Criar o controller de acesso restrito a loopback e registrar a rota.
5. Adicionar badge, metadados de origem e alternância na aba Artefatos.
6. Cobrir manifesto, acesso, filtro remoto, controller, rota e limites estruturais.

## 8. Critérios de aceite
- [x] Importar por arquivo grava origem, data, tamanho, MIME, SHA-256 e acesso `project`.
- [x] Importar por pasta registra `source: folder`.
- [x] O manifesto fica oculto no inventário e não expõe caminho absoluto.
- [x] O inventário mostra origem e acesso do artefato importado.
- [x] Artefato `local` aparece no computador e some para requisição remota, inclusive do resumo.
- [x] A alteração de acesso exige loopback e retorna 403 para acesso remoto.
- [x] Alternar o acesso pela aba atualiza a lista sem F5.
- [x] Importação anterior sem metadados continua visível e pode receber acesso.
- [x] Manifesto inválido gera aviso e não derruba o inventário.
- [x] Falha de metadados desfaz o arquivo recém-importado.
- [x] Todos os arquivos novos ficam abaixo de 300 linhas e sem emojis.
- [x] `npm test` e `npm run check` verdes.

## 9. Riscos
- **Compatibilidade:** arquivos importados antes desta história não têm origem detalhada; o inventário os marca como não registrados.
- **Segurança:** o filtro vale para o inventário e para o preview futuro; outras rotas de leitura de arquivo devem aplicar a mesma política antes de expor conteúdo.
- **Concorrência:** importações sequenciais são cobertas; escritas simultâneas de acessos podem competir pelo manifesto.
- **Rollback:** remover a rota e a alternância mantém o manifesto; apagar `artifacts/.metadata.json` volta todos os importados para `project`.
