# EP-07.02: Importação de arquivos e pastas

## 1. Identificação
- **Épico:** [EP-07](./README.md)
- **Prioridade:** P1
- **Dependências:** [EP-07.01](./07.01-inventario-artefatos.md)
- **Bloqueia:** [EP-07.03](./07.03-metadados-origem-controle-acesso.md) (metadados e acesso)

## 2. Contexto
A EP-07.01 consolidou o inventário somente leitura, mas o projeto ainda não tem um destino próprio para arquivos trazidos pelo usuário. O upload existente atende anexos de conversa, grava em `context/uploads/` e achata o nome do arquivo, sem preservar a pasta escolhida e sem integrar o resultado ao inventário de artefatos.

## 3. Objetivo
Permitir que o usuário importe arquivos individuais ou uma pasta pela aba **Artefatos**, preservando a estrutura relativa, sem sobrescrever arquivos existentes e com o resultado disponível imediatamente no inventário do projeto.

## 4. Requisitos
**Funcionais**
- RF1: importar um ou vários arquivos para `projects/<slug>/artifacts/`.
- RF2: importar uma pasta do navegador preservando até três níveis de subpastas.
- RF3: manter o arquivo original quando o nome já existir, gravando uma cópia com sufixo numérico.
- RF4: aceitar apenas extensões permitidas e arquivos de até 25 MB.
- RF5: listar os arquivos importados no inventário como tipo `imported`, com origem `artifacts`.
- RF6: a aba Artefatos oferece os botões **Importar arquivos** e **Importar pasta**, com progresso, resultado e recarga automática.
- RF7: rejeitar slug inválido, projeto inexistente, nome ausente, extensão não suportada, corpo vazio, excesso de tamanho, pasta com travessia e destino que seja symlink.

**Não funcionais**
- Arquivos de até 300 linhas, com regra de armazenamento separada do controller e da renderização.
- Ícones apenas FontAwesome. Nenhum emoji nos arquivos novos.
- Nenhum caminho absoluto é devolvido ao cliente; o destino fica sempre dentro do projeto.
- Nenhuma escrita fora de `artifacts/`, nenhum overwrite e nenhum seguimento de symlink.
- Nenhuma regressão nas abas Scrum, Mapa em Camadas, Quadro, Auditoria e Protótipos.

## 5. Arquitetura
```
[design-artifacts.js]
  botões + inputs de arquivo/pasta
          |
[design-artifacts-import.js]
  POST /api/project/:slug/artifacts/import?name=&folder=
          |
[artifact-import.controller.js]
          |
[artifact-import.service.js]
  valida extensão, tamanho, pasta e symlink
  grava em artifacts/<pasta>/<arquivo>
          |
[artifact-inventory-scan.service.js]
  artifacts/** -> kind "imported"
```

O upload usa corpo binário `application/octet-stream`, como o anexo de conversa, sem multipart. A importação de pasta é feita pelo navegador enviando os arquivos em sequência com `webkitRelativePath`. Não há manifesto nem edição de metadados nesta história; isso fica para 07.03.

## 6. Implementação
1. Criar o serviço de importação com sanitização, limite, escrita exclusiva e bloqueio de symlink.
2. Expor `POST /api/project/:slug/artifacts/import` e permitir binário nessa rota.
3. Estender a varredura do inventário para `artifacts/**` como `imported`.
4. Adicionar os botões, inputs e feedback de progresso na aba Artefatos.
5. Recarregar o inventário e os dados do projeto após a importação.
6. Cobrir armazenamento, colisão, segurança, controller, rota e limites estruturais.

## 8. Critérios de aceite
- [x] Um arquivo importado aparece em `artifacts/` e no inventário como `imported`.
- [x] Uma pasta importada preserva suas subpastas até o limite permitido.
- [x] Nome repetido não sobrescreve o arquivo anterior.
- [x] Extensão não permitida, corpo vazio e arquivo acima de 25 MB são recusados.
- [x] Pasta com `..`, caminho absoluto, profundidade excessiva ou symlink é recusada.
- [x] A aba Artefatos importa arquivos e pastas e atualiza a lista sem F5.
- [x] A rota só aceita binário no caminho de importação.
- [x] Todos os arquivos novos ficam abaixo de 300 linhas e sem emojis.
- [x] `npm test` e `npm run check` verdes.

## 9. Riscos
- **Compatibilidade:** a importação de pasta usa `webkitRelativePath`; navegadores sem suporte continuam podendo importar arquivos individuais.
- **Segurança:** nomes e pastas são sanitizados, symlinks são recusados e a rota aceita binário apenas no path de importação.
- **Desempenho:** cada arquivo é limitado a 25 MB; pastas grandes são enviadas em sequência e podem demorar.
- **Rollback:** remover a rota e os botões deixa os arquivos já importados no projeto; nenhuma migração é executada.
