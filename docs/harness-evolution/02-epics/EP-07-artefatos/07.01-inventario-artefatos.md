# EP-07.01: Inventário de artefatos por projeto

## 1. Identificação
- **Épico:** [EP-07](./README.md)
- **Prioridade:** P1
- **Dependências:** nenhuma
- **Bloqueia:** [EP-07.02](./07.02-importacao-arquivos-pastas.md) (importação), [EP-07.03](./07.03-metadados-origem-controle-acesso.md) (metadados e acesso)

## 2. Contexto
O projeto já possui artefatos em locais distintos: protótipos declarados em `projects/<slug>/design/design.json`, protótipos editáveis no Ateliê em `design/prototypes/<id>/`, conversas importadas em `chats/` e documentos/respostas gerados em `context/`. Não existe uma visão única que diga o que pertence ao projeto, onde está, qual o tipo, o tamanho e se o arquivo ainda existe.

O catálogo de protótipos em `prototype-catalog.js` cobre apenas os artefatos de design e mistura protótipos editáveis com artefatos estáticos. A API atual (`/design/index`) devolve protótipos, componentes e telas, mas não os documentos, conversas e respostas extraídas.

A EP-07.02 estende esta varredura com `artifacts/**`, classificado como `imported`; os seis tipos originais desta história permanecem inalterados.

## 3. Objetivo
Oferecer um inventário somente leitura, por projeto, que consolide os artefatos existentes com tipo, origem, caminho relativo, disponibilidade e data de modificação, sem expor caminhos absolutos nem seguir links simbólicos.

## 4. Requisitos
**Funcionais**
- RF1: listar protótipos estáticos declarados em `design/design.json`, incluindo URL externa HTTPS quando não houver arquivo local.
- RF2: listar protótipos editáveis do Ateliê a partir de `design/prototypes/*/proto.json`, com versão e quantidade de telas.
- RF3: listar conversas importadas de `chats/*.md` e documentos/respostas de `context/`.
- RF4: cada item informa `key`, `kind`, `title`, `origin`, caminho relativo, tamanho, data de modificação, MIME e disponibilidade (`local`, `external`, `missing` ou `invalid`).
- RF5: o resumo informa total, contagem por tipo, itens ausentes e itens externos.
- RF6: a UI adiciona a aba **Artefatos** na Visão 360°, com busca, filtro por tipo e tabela acessível.
- RF7: a API responde `400` para slug inválido e `404` para projeto inexistente.

**Não funcionais**
- Arquivos de até 300 linhas, separando varredura de arquivos, controller e renderização.
- Ícones apenas FontAwesome. Nenhum emoji nos arquivos novos.
- Nenhuma leitura de arquivo fora do diretório do projeto; links simbólicos não são seguidos.
- Nenhuma chamada de rede para fontes externas; URLs externas apenas são exibidas.
- Nenhuma regressão nas abas Scrum, Mapa em Camadas, Quadro, Auditoria e Protótipos.

## 5. Arquitetura
```
[artifact-inventory.service.js]
  design/design.json ------> prototype
  design/prototypes/*/proto.json -> atelier
  chats/*.md -------------> chat
  context/extraido-*.md --> extraction
  context/extraidos/documentos/** -> document
  context/extraidos/respostas/** --> response
          |
[artifact.controller.js] GET /api/project/:slug/artifacts
          |
[design-artifacts.js] aba Artefatos (busca, filtro e tabela)
```

O inventário é derivado do disco a cada chamada. Não há persistência nem migração nesta história; a importação e os metadados editáveis ficam para 07.02 e 07.03.

## 6. Implementação
1. Criar o serviço de varredura com validação de caminho, limite de itens e resumo.
2. Expor `GET /api/project/:slug/artifacts` com validação de slug e projeto.
3. Integrar a aba Artefatos ao carregamento da Visão 360°.
4. Criar a tabela com busca, filtros por tipo e estados vazio/erro.
5. Cobrir descoberta, segurança, links simbólicos, resumo e limites em teste dedicado.

## 8. Critérios de aceite
- [x] O inventário lista os seis tipos de artefato quando existirem no projeto.
- [x] Itens ausentes continuam visíveis como `missing`, sem caminho absoluto.
- [x] URL externa só é aceita com HTTPS e aparece como `external`.
- [x] Links simbólicos e caminhos com `..` não são lidos.
- [x] A API valida slug e projeto e devolve resumo consistente.
- [x] A aba Artefatos permite buscar e filtrar sem recarregar a página.
- [x] Todos os arquivos novos ficam abaixo de 300 linhas e sem emojis.
- [x] `npm test` e `npm run check` verdes.

## 9. Riscos
- **Compatibilidade:** a nova aba depende do endpoint; se ele falhar, as demais abas continuam funcionando.
- **Segurança:** a varredura é restrita ao diretório do projeto e rejeita symlinks; nenhum conteúdo de arquivo é devolvido, apenas metadados.
- **Desempenho:** o limite padrão de 500 itens evita varreduras grandes; a leitura de título é limitada aos primeiros 8 KB.
- **Rollback:** remover a aba e a rota deixa os arquivos existentes intactos; nenhuma migração é executada.
