# EP-23.05: Reinício seguro e aviso de reconexão

## 1. Identificação
- **Épico:** [EP-23](README.md)
- **Prioridade:** P1
- **Dependências:** 23.03
- **Bloqueia:** nada
- **Pode tocar além da lista acima:** `ui/engine-host.js`, `ui/public/js/modules/chat-stream-resume.js`, CSS do chat.

## 2. Contexto
Mesmo separado, o host precisa reiniciar às vezes (atualização do Harness ou das CLIs). O OpenBot espera os agentes ficarem ociosos e põe as mensagens novas na fila com o motivo `agent-restarting`. Do lado da tela, hoje a religação é silenciosa até falhar.

## 3. Objetivo
O host só reinicia com os motores ociosos, e a tela mostra "Reconectando" enquanto religa, em vez de erro.

## 4. Requisitos
**Funcionais**
- RF1. `npm run host:restart` (ou `POST /admin/restart` com token) entra em modo "drenando": recusa execuções novas com 503 e motivo `host-restarting`, espera as ativas terminarem (limite configurável, padrão 10 min) e só então reinicia.
- RF2. Passado o limite, pergunta no terminal se força o reinício; forçado, as execuções viram `interrupted` (23.02).
- RF3. Na tela, durante a religação, aparece uma faixa "Reconectando ao servidor" (ícone `fa-solid fa-rotate`) com a tentativa atual; some quando o stream volta.
- RF4. Mensagem enviada durante o modo "drenando" fica no compositor com o aviso "o servidor está reiniciando; envie em instantes", sem perder o texto.

**Não funcionais**
- Faixa acessível (`role="status"`), sem bloquear a tela.

**Fora de escopo**
- Fila persistente de mensagens no servidor.

## 5. Implementação
1. `drain.js` no host (estado, espera, limite).
2. Comando `host:restart` e rota admin.
3. `chat-connection-banner.js` ligado ao `onReattach` de `chat-stream-resume.js`.
4. Linhas no mapa.

## 6. Testes
| Tipo | Cenário | Comando ou arquivo |
|---|---|---|
| Unitário | Modo drenando recusa execução nova e espera a ativa | `node --test tests/engine-host-drain.test.js` |
| Unitário | Limite estourado com força marca `interrupted` | `tests/engine-host-drain.test.js` |
| Manual | Faixa aparece e some ao religar, nas 3 apresentações | navegador |

## 7. Critérios de aceite
- [x] `host:restart` com uma resposta em andamento espera ela terminar. (Teste com o host no processo; falta rodar contra o host de verdade.)
- [ ] A faixa "Reconectando" aparece durante a religação e some sozinha. (Ligada e testada a lógica; falta a conferência no navegador.)
- [x] Texto digitado durante o reinício não se perde.

## 8. Riscos
- **Execução presa:** sem limite, o reinício nunca acontece; o limite e a pergunta resolvem.
- **Rollback:** reinício imediato como hoje.

## 9. Evidências
Branch `feat/ep-23.05-safe-restart` (2026-11-21).

- **Drenagem:** `drain.js` guarda o estado (`idle`, `draining`, `timed-out`, `restarting`). Ao começar, o host recusa `POST /runs` com 503 e `code: "host-restarting"`, confere as execuções ativas a cada 250 ms e reinicia quando não sobra nenhuma. O limite é `HARNESS_HOST_DRAIN_MS` (padrão 10 min).
- **Rota e comando:** `GET/POST /admin/restart` com o token do host (`{}` começa, `{force: true}` força, `{cancel: true}` desiste). `npm run host:restart` (`node ui/engine-host.js --restart [--force|--cancel]`) mostra o progresso e, passado o limite, pergunta no terminal se força; sem resposta (ou fora de um terminal), cancela e o host volta a aceitar execuções.
- **Forçar:** as execuções ativas terminam como `interrupted` no diário, com evento final `reason: "restart"`, e a tela mostra o cartão da 23.04 com Retomar.
- **Reinício:** drenado, o host fecha a porta, sobe uma cópia nova destacada (log em `logs/engine-host.log`) e sai. `/health` passa a informar `drain`.
- **Tela:** `chat-connection-banner.js` mostra a faixa "Reconectando ao servidor" (`fa-solid fa-rotate`, `role="status"`, sem bloquear a tela nem tirar o foco) com a tentativa, a partir do `onReattach`, e some no `onReconnected` ou no fim da resposta. Uma faixa só para a página, então vale para as 3 apresentações.
- **Texto preservado:** mensagem recusada com `host-restarting` sai da conversa e volta para o compositor (sem sobrescrever o que já tiver sido digitado), com o aviso "O servidor está reiniciando; envie em instantes".
- **Testes:** `tests/engine-host-drain.test.js` (6); suíte inteira 2897 passando.
- **Fora da lista `owns`:** `ui/engine-host.js`, `host-routes.js`, `chat-run-registry.service.js` (`interrupt()`), `chat-stream-resume.js` (`onReconnected`), `chat-send.js`, CSS `06-chat-system-cards.css`, `package.json`.
- **Pendente:** rodar `npm run host:restart` contra o host real com uma resposta longa em andamento; conferir a faixa no navegador. Anexos da mensagem recusada não voltam ao compositor, só o texto. O modo comparativo não mostra a faixa.
