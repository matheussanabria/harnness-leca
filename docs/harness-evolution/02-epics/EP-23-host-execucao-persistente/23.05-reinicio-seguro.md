# EP-23.05: Reinício seguro e aviso de reconexão

## 1. Identificação
- **Épico:** [EP-23](README.md)
- **Prioridade:** P1
- **Dependências:** 23.03
- **Bloqueia:** nada
- **Pode tocar além da lista acima:** `ui/engine-host.js`, `ui/public/js/modules/chat-stream-resume.js`, CSS do chat.

## 2. Contexto
Mesmo separado, o host precisa reiniciar às vezes (atualização do Harness ou das CLIs). O OpenBot espera os agentes ficarem ociosos e põe as mensagens novas na fila com o motivo `agent-restarting`. Do lado da tela, hoje a religação é silenciosa até falhar.

## 3. Objetivo
O host só reinicia com os motores ociosos, e a tela mostra "Reconectando" enquanto religa, em vez de erro.

## 4. Requisitos
**Funcionais**
- RF1. `npm run host:restart` (ou `POST /admin/restart` com token) entra em modo "drenando": recusa execuções novas com 503 e motivo `host-restarting`, espera as ativas terminarem (limite configurável, padrão 10 min) e só então reinicia.
- RF2. Passado o limite, pergunta no terminal se força o reinício; forçado, as execuções viram `interrupted` (23.02).
- RF3. Na tela, durante a religação, aparece uma faixa "Reconectando ao servidor" (ícone `fa-solid fa-rotate`) com a tentativa atual; some quando o stream volta.
- RF4. Mensagem enviada durante o modo "drenando" fica no compositor com o aviso "o servidor está reiniciando; envie em instantes", sem perder o texto.

**Não funcionais**
- Faixa acessível (`role="status"`), sem bloquear a tela.

**Fora de escopo**
- Fila persistente de mensagens no servidor.

## 5. Implementação
1. `drain.js` no host (estado, espera, limite).
2. Comando `host:restart` e rota admin.
3. `chat-connection-banner.js` ligado ao `onReattach` de `chat-stream-resume.js`.
4. Linhas no mapa.

## 6. Testes
| Tipo | Cenário | Comando ou arquivo |
|---|---|---|
| Unitário | Modo drenando recusa execução nova e espera a ativa | `node --test tests/engine-host-drain.test.js` |
| Unitário | Limite estourado com força marca `interrupted` | `tests/engine-host-drain.test.js` |
| Manual | Faixa aparece e some ao religar, nas 3 apresentações | navegador |

## 7. Critérios de aceite
- [ ] `host:restart` com uma resposta em andamento espera ela terminar.
- [ ] A faixa "Reconectando" aparece durante a religação e some sozinha.
- [ ] Texto digitado durante o reinício não se perde.

## 8. Riscos
- **Execução presa:** sem limite, o reinício nunca acontece; o limite e a pergunta resolvem.
- **Rollback:** reinício imediato como hoje.
