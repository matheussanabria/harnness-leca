# EP-23.01: Main sem auto restart

## 1. Identificação
- **Épico:** [EP-23](README.md)
- **Prioridade:** P0
- **Dependências:** nenhuma
- **Bloqueia:** nada; é o paliativo até a 23.03
- **Pode tocar além da lista acima:** `package.json` (só os scripts `ui` e `ui:dev`).

## 2. Contexto
O checkout principal é onde o usuário conversa pela interface. Mudanças de código passam por worktree, teste e revisão antes de chegar nele, então o auto restart (`ui:dev`) não traz ganho ali e derruba respostas em andamento. O [SETUP.md](../../../../SETUP.md) hoje recomenda `npm run ui:dev` como laço de desenvolvimento, sem distinguir checkout principal de worktree.

## 3. Objetivo
O checkout principal roda sem watch por padrão, e quem usa `ui:dev` lá recebe um aviso claro.

## 4. Requisitos
**Funcionais**
- RF1. `SETUP.md` separa os dois usos: `npm run ui` para uso diário (checkout principal) e `npm run ui:dev` só dentro de um worktree de desenvolvimento.
- RF2. `.claude/launch.json` mantém `harness-ui` sem watch (já está assim) e ganha uma entrada `harness-ui-dev` com watch, para worktrees.
- RF3. Ao subir com watch fora de um worktree (`git rev-parse --git-dir` igual a `--git-common-dir`), o servidor escreve um aviso no terminal: "auto restart no checkout principal derruba respostas do chat; use npm run ui".
- RF4. O aviso não impede a subida (é aviso, não bloqueio).

**Fora de escopo**
- Persistência e separação de processo (23.02 e 23.03).

## 5. Implementação
1. Criar `tools/lib/ui-dev-guard.js` com `isMainCheckout(cwd)` e `warnIfWatchOnMain()`; detectar watch por `process.execArgv` contendo `--watch` ou `--watch-path`.
2. Chamar o guard no início de `ui/server.js`.
3. Atualizar `SETUP.md` e `.claude/launch.json`.
4. Linha no mapa para o guard e o teste.

## 6. Testes
| Tipo | Cenário | Comando ou arquivo |
|---|---|---|
| Unitário | Checkout principal com watch gera aviso; worktree com watch não gera; sem watch não gera | `node --test tests/ui-dev-guard.test.js` |
| Regressão | Servidor sobe normalmente com e sem watch | `node --test tests/server.test.js` |

## 7. Critérios de aceite
- [x] Subir `npm run ui:dev` no checkout principal mostra o aviso e o servidor sobe. (Verificado em 2026-11-22 rodando o comando real; o aviso só aparece depois da correção do guard, ver Evidências.)
- [x] Subir `npm run ui:dev` num worktree não mostra aviso. (Verificado em 2026-11-22 rodando o comando real num worktree.)
- [x] `SETUP.md` descreve os dois usos.

## 8. Riscos
- **Detecção do worktree:** o teste precisa limpar `GIT_DIR` e `GIT_INDEX_FILE` do ambiente (ver memória git-hook-env-leaks-into-tests).
- **Rollback:** remover a chamada do guard em `ui/server.js`.

## 9. Evidências
Preencher ao concluir.
- **Divergência:** a primeira versão do guard nunca avisava no uso real: no modo watch o Node roda o servidor num processo filho cujo `process.execArgv` perdeu `--watch` e `--watch-path` (fica só `--watch-preserve-output`) e que tem `WATCH_REPORT_DEPENDENCIES`. Os testes passavam porque injetavam o `execArgv`. Corrigido em 2026-11-22; o novo teste roda o guard dentro de um `node --watch-path` de verdade, num checkout principal e num worktree, e falha no guard antigo.
