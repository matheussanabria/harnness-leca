# EP-23.06: Seletor de host: local e VPS

## 1. Identificação
- **Épico:** [EP-23](README.md)
- **Prioridade:** P2
- **Dependências:** 23.03; para uso fora da rede local, depende de autenticação (EP-17.04) ou de um túnel privado (Tailscale)
- **Bloqueia:** nada; prepara o mobile (EP-20) e um futuro desktop
- **Pode tocar além da lista acima:** cabeçalho da interface, `SETUP.md`.

## 2. Contexto
O OpenBot lista vários hosts (por exemplo "Desktop-Local" e "Desktop-VPS"), e cada um tem o próprio banco. O cliente consulta o host escolhido; não há sincronização entre bancos. O Harness vai rodar também na VPS (Easypanel, com Traefik e HTTPS), e o celular usa a interface web.

## 3. Objetivo
A mesma interface aponta para o host local ou para o host da VPS, um de cada vez, e mostra qual está em uso.

## 4. Requisitos
**Funcionais**
- RF1. Lista de hosts em `data/hosts.json` (nome, URL base, token), editável pela tela; o token nunca volta inteiro para o navegador depois de salvo (só os 4 últimos caracteres).
- RF2. Seletor no cabeçalho com o host atual e o estado de cada um (no ar, fora do ar, versão incompatível), lido do `/health` de cada host.
- RF3. Trocar de host troca projetos, conversas e execuções exibidos; nada é copiado entre hosts.
- RF4. Host remoto só por HTTPS ou por endereço de túnel privado; HTTP em endereço público é recusado.

**Não funcionais**
- Acessível por teclado; FontAwesome, zero emojis.
- Nenhum host fica exposto sem autenticação: a VPS publica o Harness só atrás do Traefik com autenticação, ou só pelo Tailscale.

**Fora de escopo**
- Conta central como a do OpenBot, sincronização de bancos e WebRTC. App desktop.

## 5. Arquitetura
- Cada host tem o próprio `data/harness.sqlite`. Nenhum host escreve no banco de outro, então vários hosts não disparam a revisão do ADR-012 que considera Postgres (ver decisão 6 do [README](README.md)).
- O navegador fala com o servidor web do host escolhido. Para o local é `localhost`; para a VPS é o domínio HTTPS dela. Não precisamos de um serviço como o Signal do OpenBot, porque os hosts são poucos e conhecidos.

## 6. Implementação
1. `host-registry.js` (ler, validar URL e esquema, mascarar token, checar `/health`).
2. `host-selector.js` no cabeçalho.
3. Documentar em `SETUP.md` o host na VPS (Easypanel, Traefik, autenticação ou Tailscale).
4. Linhas no mapa.

## 7. Testes
| Tipo | Cenário | Comando ou arquivo |
|---|---|---|
| Unitário | URL HTTP pública recusada; HTTPS e túnel aceitos; token mascarado | `node --test tests/host-registry.test.js` |
| Integração | Dois hosts de teste em portas diferentes: trocar mostra conversas diferentes | `tests/host-registry.test.js` |
| Manual | Abrir a VPS pelo celular e pelo PC | navegador |

## 8. Critérios de aceite
- [ ] O seletor mostra o host local e o da VPS com o estado de cada um. (Conferido no navegador com um host local; falta a VPS de verdade.)
- [x] Trocar de host troca o conteúdo sem misturar dados. (Abrir carrega a interface do outro host; nada é copiado.)
- [x] Nenhum host remoto é aceito por HTTP público.

## 9. Riscos
- **Segurança:** expor o host na internet sem autenticação; o RF4 e o requisito não funcional são obrigatórios.
- **Rollback:** esconder o seletor e usar só o host local.

## 10. Evidências
Branch `feat/ep-23.06-host-selector` (2026-11-22).

- **Registro:** `data/hosts.json` (fora do git, permissão 0600) com nome, URL e o PIN de acesso do host remoto. O PIN só serve para este servidor ler o `/api/host/info` do outro host (cabeçalho `X-Harness-Pin`, que a autenticação remota já aceitava); o navegador nunca recebe o PIN inteiro.
- **Estados:** no ar, fora do ar, PIN incorreto ou ausente (401/429) e versão incompatível (`protocol` diferente), cada um com ícone e texto. A conferência é feita pelo servidor, em paralelo, com 3 s de limite.
- **Trocar de host:** "Abrir" carrega a interface do outro host na mesma aba; ele pede o próprio PIN quando precisa. Cada host tem o próprio banco; nada é copiado (RF3).
- **RF4:** HTTPS sempre; HTTP só em loopback, rede privada (10.x, 172.16-31.x, 192.168.x) e Tailscale (100.64.0.0/10, `*.ts.net`). URL com usuário ou senha é recusada. Conferido no navegador: uma URL HTTP pública mostra o erro e não é salva.
- **Navegador:** botão "Host" no cabeçalho, painel acessível por teclado (Esc fecha, foco visível) e sempre dentro da tela (na primeira versão ele abria cortado à esquerda; corrigido).
- **Testes:** `tests/host-registry.test.js` (5), com quatro hosts reais de teste (no ar, PIN errado, versão antiga, desligado) consultados pelo servidor de verdade.
- **Divergências:** a história pedia os 4 últimos caracteres do token; como o PIN de acesso tem 6 dígitos, isso entregaria quase todo o PIN, então segredos de até 8 caracteres mostram só os 2 últimos. O token do host é o PIN de acesso remoto já existente, não um token novo. A lista é editada por qualquer acesso autenticado à interface, não só pelo loopback.
- **Aceite:** Aceita em 2026-11-23 por decisão do usuário: o Harness ainda não existe na VPS, então as conferências que dependem dela ou do navegador ficam como pendências.
- **Pendente:** cadastrar a VPS de verdade e abrir pelo celular e pelo PC; a 23.07 (host por checkout) ainda vai dar identidade própria a cada host de motores.
