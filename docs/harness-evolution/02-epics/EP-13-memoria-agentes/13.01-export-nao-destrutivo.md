# EP-13.01: Export não destrutivo, sem sugestões e com medição de tokens

## 1. Identificação
- **Épico:** [EP-13](README.md)
- **Prioridade:** P0
- **Dependências:** nenhuma
- **Bloqueia:** 13.08

## 2. Contexto
`tools/export-context.js:167` sobrescreve o `MEMORY.md` do Claude Code a cada execução; `:170` e `:207-208` exportam `extraido-regras.md` (sugestões) e `:176`/`:208` exportam `extraido-conversas.md` (140 KB) como memória. Ver [diagnóstico](00-diagnostico.md), P1 a P4 e P7.

## 3. Objetivo
Rodar `npm run export:context` não apaga nada que o harness não gerou e só envia memória curada. O usuário vê quanto cada motor recebe.

## 4. Requisitos
**Funcionais**
- RF1. No `MEMORY.md` do Claude Code, escrever só entre `<!-- harness:begin -->` e `<!-- harness:end -->`. Conteúdo fora do bloco é preservado byte a byte. Se o arquivo não tiver o bloco, acrescentá-lo ao fim.
- RF2. O bloco do Claude tem só um ponteiro ("a memória curada do harness chega pelo hook em `<project-harness>`"), sem repetir fatos.
- RF3. Parar de gerar `regras-e-diretrizes.md`, `historico-conversas.md` e `memorias-consolidadas.md` na pasta do Claude e `regras.md`/`conversas-indice.md` no Knowledge Item. Os arquivos já gerados só são removidos com `--prune` e confirmação, listando cada caminho.
- RF4. Arquivo gerado pelo harness leva a linha `<!-- harness:generated -->`; o export só reescreve arquivos com esse marcador.
- RF5. `--report` imprime, por projeto e motor, os bytes e uma estimativa de tokens (bytes / 4) do que é injetado, antes e depois.
- RF6. Remover emojis dos logs.

**Não funcionais**
- Dividir `tools/export-context.js` em fachada + `tools/lib/export/{claude,gemini,local}.js`, cada um com menos de 250 linhas.
- Ícones apenas FontAwesome. Nenhum emoji.

## 5. Arquitetura
A fachada coleta os dados do projeto e chama um escritor por destino. `writeManagedBlock(file, content)` e `writeGenerated(file, content)` ficam em `tools/lib/export/managed-file.js`.

## 6. Implementação
1. Extrair os três escritores sem mudar a saída (commit de refatoração pura).
2. Introduzir `managed-file.js` e trocar o `MEMORY.md` para bloco gerenciado.
3. Remover a exportação de sugestões e histórico; adicionar `--prune`.
4. Adicionar `--report`.
5. Verificar se `.claude/context/` e `.gemini/context/` têm consumidor; se não tiver, registrar e propor remoção ao usuário.

## 7. Testes
| Tipo | Cenário | Comando ou arquivo |
|---|---|---|
| Unitário | Bloco gerenciado preserva conteúdo fora dos marcadores | `node --test tests/export-managed-file.test.js` |
| Unitário | Arquivo sem `harness:generated` não é reescrito | idem |
| Integração | `--dry-run` em diretório temporário não toca em `~` | `node --test tests/export-context.test.js` |
| Regressão | Golden master | `npm test` |

## 8. Critérios de aceite
- [ ] Um `MEMORY.md` com linhas escritas pelo Claude Code sobrevive a duas execuções seguidas do export.
- [ ] Nenhum arquivo da pasta do Claude ou do Knowledge Item contém texto de `context/extraido-*.md`.
- [ ] `--report` mostra a queda de bytes do Knowledge Item do `harness-leca` (de ~172 KB para a memória curada).
- [ ] Nenhum arquivo do export passa de 250 linhas; nenhum emoji.

## 9. Riscos
- **Compatibilidade:** o Antigravity pode depender de `metadata.artifacts`; atualizar a lista junto.
- **Segurança:** escrever fora do repo exige caminhos validados contra `~/.claude/projects` e `~/.gemini`.
- **Rollback:** reverter o commit; os arquivos antigos só somem com `--prune`.

## 10. Evidências
- Implementado: fachada `tools/export-context.js` (115 linhas) e `tools/lib/export/{claude,gemini,local,managed-file,data,housekeeping}.js` (todos abaixo de 120 linhas).
- Testes: `tests/export-managed-file.test.js` e `tests/export-context.test.js` (13 testes verdes); `npm test`: 1005 testes, 0 falhas; `npm run check` sem erro.
- `--dry-run --report` para `harness-leca` (bytes/tokens, antes -> depois): claude 1046443/261611 -> 1038/260 (soma de todas as pastas do Claude mapeadas); gemini (Knowledge Item + regra global) 172877/43220 -> 1966/492; local 64906/16227 -> 3190/798.
- `--prune` sem `--yes` só lista (83 arquivos antigos no total, todos os projetos); `--prune --yes` não foi executado.
- Passo 5: nenhum código lê `.claude/context` nem `.gemini/context`; só o próprio export (produtor) e documentação (`docs/setup/interface-e-desenvolvimento.md`, `docs/PLAN-commit-atomico.md`, `docs/harness-jira/01-diagnostico-integracao-jira.md:208`, que cita `.claude/context/saude-dispensacao.md:20` como registro de decisão). Remoção proposta ao usuário; nada removido.
- Decisão: arquivos gerados por versões anteriores (sem marcador) são reconhecidos por cabeçalho legado para poderem ser migrados; JSON recebe o marcador no campo `generator`.
