# EP-13.09: Faxina periódica com relatório

## 1. Identificação
- **Épico:** [EP-13](README.md)
- **Prioridade:** P2
- **Dependências:** 13.04
- **Bloqueia:** nenhuma

## 2. Contexto
Memória envelhece: arquivos citados são movidos, decisões de projeto expiram, itens parecidos se acumulam. A skill `knowledge-curation` já descreve o "pente"; falta o script.

## 3. Objetivo
Um comando aponta o que provavelmente está errado ou velho na memória curada, sem apagar nada.

## 4. Requisitos
**Funcionais**
- RF1. `node tools/memory.js lint [--project <slug> | --all] [--json]` verifica:
  - duplicata exata (hash) e provável (similaridade acima de 0,8);
  - caminhos citados no corpo (padrão `tools/...`, `ui/...`, `docs/...`, `projects/...`) que não existem mais;
  - `[[wikilinks]]` sem item correspondente (só aviso: link para memória futura é permitido);
  - itens `project` com `updated` há mais de 60 dias;
  - itens que falham no contrato ou no guard;
  - índice acima de 80% do teto.
- RF2. Relatório em Markdown em `projects/<slug>/context/faxina-memoria.md`, com uma ação sugerida por achado (atualizar, juntar, arquivar).
- RF3. Código de saída 1 só para contrato e guard; os demais são avisos.
- RF4. Opcional: rotina em `projects/<slug>/scheduled/` para rodar semanalmente, criada só com pedido do usuário.

**Não funcionais**
- Somente leitura sobre `memory/`.
- Sem modelo.

## 5. Arquitetura
`tools/lib/memory/lint.js` com uma função por verificação, cada uma devolvendo `{ regra, item, mensagem, acao }`.

## 6. Implementação
1. Verificações uma a uma, com teste.
2. Relatório e `--json`.
3. Integrar contrato e guard ao `npm run check`.

## 7. Testes
| Tipo | Cenário | Comando ou arquivo |
|---|---|---|
| Unitário | Cada regra dispara no caso positivo e não no negativo | `node --test tests/memory-lint.test.js` |
| Unitário | Lint não altera nenhum arquivo de `memory/` | idem |

## 8. Critérios de aceite
- [ ] Lint do `harness-leca` roda em menos de 2 s e gera o relatório.
- [ ] `npm run check` falha com item fora do contrato.

## 9. Riscos
- **Ruído:** caminhos citados como exemplo geram falso positivo; permitir `<!-- lint:ignore caminho -->` no item.
- **Rollback:** remover a integração com o `check`.
