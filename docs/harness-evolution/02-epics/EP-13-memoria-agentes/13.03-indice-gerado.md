# EP-13.03: Índice gerado por script com teto

## 1. Identificação
- **Épico:** [EP-13](README.md)
- **Prioridade:** P0
- **Dependências:** 13.02
- **Bloqueia:** 13.04, 13.05, 13.07

## 2. Contexto
Índice escrito à mão diverge dos arquivos: o `MEMORY.md` do Claude aponta para `memorias-consolidadas.md`, que não existe (diagnóstico, P2).

## 3. Objetivo
`node tools/memory.js index` monta `memory.md` a partir das `description` dos itens, sempre igual para a mesma entrada.

## 4. Requisitos
**Funcionais**
- RF1. Ler `projects/<slug>/memory/**/*.md` (ou `global/memory/`) via `tools/lib/memory/store.js`.
- RF2. Gerar o índice no formato da [arquitetura-alvo, seção 4](01-arquitetura-alvo.md#4-índice-gerado-1303), agrupado por tipo e ordenado por `name`.
- RF3. Teto de 150 linhas: acima disso, falhar com código 2 e listar os itens `project` mais antigos como candidatos a arquivar.
- RF4. Item que não passa no contrato não entra no índice e aparece no relatório de erros (não interrompe os demais).
- RF5. `--check` não grava; sai com 1 se o índice em disco estiver desatualizado (para o pre-commit).
- RF6. Se a pasta `memory/` não existir, não fazer nada (compatível com projetos ainda não migrados).

**Não funcionais**
- `tools/lib/memory/index.js` e `store.js` com menos de 250 linhas cada; `tools/memory.js` só faz o roteamento de subcomandos.

## 5. Arquitetura
`store.listItems(scope)` devolve itens já validados; `index.render(items, { today })` é função pura. A data entra por parâmetro para o teste ser determinístico.

## 6. Implementação
1. `store.js` com leitura tolerante a BOM (como o hook).
2. `index.js` puro, com teste de snapshot.
3. Subcomando `index` e `--check`.
4. Ligar `--check` ao `scripts/pre-commit.js` só para projetos que já têm `memory/`.

## 7. Testes
| Tipo | Cenário | Comando ou arquivo |
|---|---|---|
| Unitário | Mesma entrada, mesmo índice | `node --test tests/memory-index.test.js` |
| Unitário | Teto estourado falha com a lista de candidatos | idem |
| Unitário | Item inválido fica fora e é reportado | idem |
| Integração | `--check` detecta índice desatualizado | idem |

## 8. Critérios de aceite
- [ ] Índice gerado duas vezes seguidas sem diff.
- [ ] Pre-commit barra commit com item novo e índice antigo.

## 9. Riscos
- **Compatibilidade:** o pre-commit só olha projetos migrados.
- **Rollback:** remover o gancho do pre-commit.
