# EP-04.05: Proteção de alterações não salvas

## 1. Identificação
- **Épico:** [EP-04](README.md)
- **Prioridade:** P1
- **Dependências:** EP-04.01 a EP-04.04
- **Bloqueia:** encerramento do EP-04 e integração completa do EP-06

## 2. Contexto
O editor de fonte do Studio já identifica alterações locais, mas essa informação não chega ao seletor central de projeto nem ao carregador de layouts. Assim, um consumidor pode trocar o contexto inteiro sem que a plataforma saiba que existe trabalho pendente.

## 3. Objetivo
Publicar um registro compartilhado de alterações não salvas e usá-lo como guard nas trocas de projeto e workspace, com bloqueadores estruturados e bypass somente após confirmação explícita do consumidor.

## 4. Requisitos
**Funcionais**
- RF1. Consumidores registram uma pendência por ID, rótulo e escopo opcional de projeto/workspace.
- RF2. O registro permite listar, consultar, assinar e limpar pendências sem depender do DOM.
- RF3. Trocar de projeto com pendências do projeto atual lança erro `UNSAVED_CHANGES` antes de sincronizar o backend.
- RF4. Carregar um workspace com pendências aplicáveis lança o mesmo erro antes de alterar janelas.
- RF5. Uma interface que já confirmou a decisão pode repetir a transição com `force: true`.
- RF6. Projeto, workspace e janelas atuais permanecem intactos quando a transição é bloqueada.

**Não funcionais**
- Contrato compartilhado abaixo de 200 linhas e sem dependência visual.
- Nenhum `confirm` embutido na plataforma; texto e acessibilidade pertencem ao consumidor visual.
- Nenhuma alteração em arquivos `chat*`, `office*` ou consumidores do Studio da trilha Gemini.

## 5. Contrato publicado
```js
windowManager.unsaved.mark("studio:source", {
  label: "Fonte do Studio",
  projectSlug,
  workspaceId
});

windowManager.unsaved.clear("studio:source");
windowManager.workspaces.load("quality", viewport, projectSlug, { force: true });
projectSelection.select(nextProject, { force: true });
```

O erro possui `code: "UNSAVED_CHANGES"` e `blockers`, uma lista imutável de fontes identificadas. A interface deve exibir esses bloqueadores, oferecer salvar/cancelar/descartar e usar `force` apenas depois da escolha explícita do usuário.

## 6. Implementação
1. Criar `UnsavedChangesRegistry` compartilhado e observável.
2. Consultar o registro antes de trocar o projeto central.
3. Injetar o guard em `WorkspaceSession` antes de aplicar um layout válido.
4. Publicar a API pela fachada `windowManager.unsaved`.
5. Preservar as assinaturas existentes e adicionar `force` como opção compatível.

| Tipo | Cenário | Arquivo |

| Regressão | Presets e persistência continuam carregáveis | `tests/workspace-presets.test.js`, `tests/workspace-persistence.test.js` |

## 8. Critérios de aceite
- [x] Pendências podem ser registradas e removidas por qualquer módulo.
- [x] O seletor central bloqueia troca de projeto antes de efeitos externos.
- [x] A sessão bloqueia troca de workspace antes de alterar janelas.
- [x] O erro identifica todas as fontes que impedem a transição.
- [x] O bypass exige `force: true` explícito e mantém retrocompatibilidade.
- [x] Testes focados e `npm run check` passam.

## 9. Handoff para Gemini / EP-06
- O Studio deve chamar `windowManager.unsaved.mark` quando `setDirty(true)` ocorrer e `clear` após salvar ou descartar.
- O seletor visual deve capturar `UNSAVED_CHANGES`, listar `blockers` e só repetir com `force` após confirmação.
- A plataforma não altera nem descarta conteúdo; essa decisão continua no módulo proprietário.

- Checagem de tipos focada dos módulos compartilhados: sem erro; débitos anteriores do Window Manager permanecem fora do escopo.
