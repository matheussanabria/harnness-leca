# EP-04.02: Layouts nomeados

## 1. Identificação
- **Épico:** [EP-04](README.md)
- **Prioridade:** P1
- **Dependências:** EP-04.01 e EP-01.10
- **Bloqueia:** 04.03 e 04.04

## 2. Contexto
O `WorkspacePresetManager` da EP-01.10 já salva, lista, carrega e exclui presets, mas não é consumido pela fachada do Window Manager. Na prática, somente os testes conseguem acessá-lo. A restauração também usa IDs serializados depois de reabrir janelas, o que falha para módulos não singleton cujo novo ID é diferente.

## 3. Objetivo
Publicar layouts nomeados como uma capacidade oficial do Window Manager, vinculada ao projeto selecionado pela EP-04.01, com estado observável e restauração correta de todas as janelas.

## 4. Requisitos
**Funcionais**
- RF1. Expor listagem, salvamento, carregamento e exclusão pela fachada `windowManager.workspaces`.
- RF2. Usar por padrão o projeto ativo do contrato central de seleção.
- RF3. Isolar layouts customizados por projeto e rejeitar operações sem projeto válido.
- RF4. Informar o workspace atualmente carregado e notificar assinantes após operações bem-sucedidas.
- RF5. Restaurar foco e minimização usando os IDs reais retornados ao reabrir janelas singleton e não singleton.
- RF6. Impedir exclusão dos presets de sistema e limpar o estado ativo ao excluir o customizado carregado.

**Não funcionais**
- Integração modular, sem adicionar UI aos arquivos `office*` pertencentes à trilha Gemini.
- Novo módulo abaixo de 200 linhas; não ampliar o arquivo de presets além do necessário para corrigir a restauração.
- Ícones exclusivamente FontAwesome e nenhum emoji novo.
- Compatibilidade com a API existente de `WorkspacePresetManager`.

## 5. Arquitetura
- `workspace-presets.js`: armazenamento e aplicação do layout; continua sendo a camada de persistência.
- `workspace-session.js`: contexto do projeto, workspace ativo, operações e eventos.
- `window-manager.js`: fachada pública `workspaces`, sem DOM.
- `project-selection.js`: fonte padrão do projeto atual.

## 6. Implementação
1. Proteger o comportamento esperado com testes.
2. Corrigir o mapeamento de IDs durante a restauração.
3. Criar a sessão de layouts nomeados orientada ao projeto ativo.
4. Publicar a sessão na fachada do Window Manager.
5. Executar regressão do Window Manager e registrar evidências.

## 7. Testes
| Tipo | Cenário | Comando ou arquivo |
|---|---|---|
| Unitário | CRUD, isolamento e notificações da sessão | `tests/workspace-session.test.js` |
| Unitário | Restauração de módulo não singleton | `tests/workspace-presets.test.js` |
| Integração | Fachada usa o projeto central selecionado | `tests/workspace-session.test.js` |
| Regressão | Window Manager e persistência | `node --test tests/workspace-session.test.js tests/workspace-presets.test.js tests/window-manager.test.js tests/layout-persistence.test.js` |

## 8. Critérios de aceite
- [x] `windowManager.workspaces` oferece CRUD de layouts nomeados.
- [x] O projeto ativo é usado sem duplicar a resolução da EP-04.01.
- [x] Layouts customizados não vazam entre projetos.
- [x] Módulos não singleton recuperam foco e estado minimizado corretamente.
- [x] Assinantes recebem snapshots apenas após operações válidas.
- [x] Presets de sistema continuam protegidos.
- [x] Testes focados e `npm run check` passam.

## 9. Riscos
- **Compatibilidade:** a classe da EP-01.10 permanece exportada com a mesma API.
- **Concorrência:** nenhuma UI do Escritório será editada nesta história.
- **Rollback:** remover a sessão da fachada mantém o gerenciador de presets original intacto.
