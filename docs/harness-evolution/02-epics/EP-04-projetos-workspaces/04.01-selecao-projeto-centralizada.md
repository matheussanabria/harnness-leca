# EP-04.01: Seleção de projeto centralizada

## 1. Identificação
- **Épico:** [EP-04](README.md)
- **Prioridade:** P1
- **Dependências:** EP-01 concluído
- **Bloqueia:** 04.02, 04.03, 04.04, 04.05, EP-05 e EP-06

## 2. Contexto
A interface principal resolve o projeto em `app.js`, enquanto o Escritório repete a precedência e a persistência em `office-state.js`. A seleção é espalhada entre query string, `localStorage`, `projects/.active` e o estado carregado da API. A interface principal não sincroniza a troca com `POST /api/project/active`, criando risco de cada superfície apontar para um projeto diferente.

## 3. Objetivo
Oferecer um único contrato de seleção de projeto para todas as superfícies web, mantendo URL, navegador e backend coerentes antes de notificar os consumidores.

## 4. Requisitos
**Funcionais**
- RF1. Resolver a seleção inicial na ordem: query string válida, preferência local válida, projeto ativo do backend e primeiro projeto disponível.
- RF2. Canonicalizar o slug sem diferenciar maiúsculas e rejeitar projetos fora do catálogo.
- RF3. Persistir uma troca confirmada em `localStorage`, na query string `p` e em `projects/.active` por API.
- RF4. Expor assinatura para consumidores reagirem a uma troca confirmada.
- RF5. Manter o projeto anterior quando a sincronização com o backend falhar.
- RF6. Fazer a interface principal e o Escritório usarem o mesmo contrato.

**Não funcionais**
- Arquivos de código abaixo de 250 linhas e responsabilidades separadas entre store frontend, serviço backend e controller.
- Nenhum acesso a módulos de Chat pertencentes à trilha Gemini.
- Escrita de `projects/.active` atômica e restrita a slugs existentes.
- Nenhum emoji novo em código ou interface.

## 5. Arquitetura
- `shared/project-selection.js`: resolução, persistência web, sincronização HTTP e assinatura.
- `project-selection.service.js`: validação canônica e escrita atômica de `projects/.active`.
- `project.controller.js`: permanece como adaptador HTTP fino.
- `app.js` e `office-state.js`: consumidores do contrato compartilhado.

## 6. Implementação
1. Proteger o comportamento com testes do contrato e do serviço.
2. Extrair a escrita do projeto ativo do controller.
3. Integrar o store compartilhado na interface principal.
4. Substituir a seleção duplicada do Escritório.
5. Executar testes focados, checagem sintática e regressão relevante.

## 7. Testes
| Tipo | Cenário | Comando ou arquivo |
|---|---|---|
| Unitário | Precedência e canonicalização | `tests/project-selection.test.js` |
| Unitário | Persistência, evento e rollback | `tests/project-selection.test.js` |
| Integração | Escrita canônica e atômica do ativo | `tests/project-selection.test.js` |
| Regressão | Rotas de projeto e workspaces existentes | `node --test tests/project-selection.test.js tests/server.test.js tests/workspace-presets.test.js` |

## 8. Critérios de aceite
- [x] Existe apenas um contrato frontend para resolver e trocar o projeto ativo.
- [x] Interface principal e Escritório consomem esse contrato.
- [x] URL, armazenamento local e backend convergem para o mesmo slug canônico.
- [x] Falha HTTP não publica uma seleção que o backend recusou.
- [x] Projeto desconhecido é rejeitado sem alterar estado persistido.
- [x] Testes focados e `npm run check` passam.

## 9. Riscos
- **Compatibilidade:** consumidores legados ainda leem `state.P` ou `officeState.activeProject`; ambos serão mantidos como projeções.
- **Segurança:** o backend continua aceitando somente slugs do catálogo e requisições POST protegidas pela política de origem.
- **Rollback:** remover os adaptadores e restaurar a resolução local anterior em `app.js` e `office-state.js`.

## 10. Evidências
- Arquivos alterados: `shared/project-selection.js`, `project-selection.service.js`, `project.controller.js`, `app.js`, `office-state.js`, `project-selection.test.js` e `server.test.js`.
- Comandos executados e resultado: testes focados 18/18; `npm run check` aprovou 443 JS e 10 JSON; typecheck global continua vermelho sem erros novos nos arquivos da história.
- Capturas: não aplicável para mudança de contrato sem alteração visual.
