# EP-08.07: Gestão Global de Workflows no Catálogo e Roteamento Canônico com Histórico

[Voltar ao épico](./README.md)

## 1. Identificação
- **Épico:** [EP-08](./README.md)
- **Prioridade:** P1
- **Dependências:** [EP-08.01](./08.01-catalogo-capacidades.md), [EP-08.06](./08.06-ui-workflows.md)
- **Bloqueia:** nenhum.

## 2. Contexto
Anteriormente, a visualização e execução de workflows estava restrita ao escopo de projetos individuais (aba Workflows do Design), sem presença no Catálogo Global (`/catalogo`) ao lado de Agentes e Skills. Além disso, a navegação no Catálogo não mantinha rotas canônicas amigáveis (ex: `/catalogo/workflows/:id`, `/catalogo/skills/:id`, `/catalogo/agents/:id`), impedindo o uso natural do botão "Voltar" do navegador ou do botão de interface (`#kBack`) para retornar à etapa anterior após navegar em cross-references de workflows para skills ou agentes.

## 3. Objetivo
1. Centralizar a descoberta e inspeção de Workflows no Catálogo Global (`/catalogo`) com suporte a múltiplas fontes (`~/.gemini/workflows`, `~/.claude/workflows`, `.agents/workflows`, `projects/<slug>/workflows` e definições embutidas).
2. Resolver a disponibilidade de skills globais do usuário e do harness no `workflow-plan.service.js`, eliminando falsos avisos de skills ausentes.
3. Implementar roteamento canônico cliente/servidor com History API (`pushState`, `replaceState`, `popstate`), permitindo links diretos, refresh (F5), favoritos e navegação suave de volta.

## 4. Requisitos
**Funcionais**
- RF1: Aba "Workflows" no Catálogo Global com contadores e busca textual por nome/descrição.
- RF2: Rotas canônicas `/catalogo/:kind` e `/catalogo/:kind/:id` para `skills`, `agents` e `workflows`.
- RF3: O servidor estático (`static.controller.js`) serve `catalogo.html` para `/catalogo` e `/catalogo/*`.
- RF4: O botão `#kBack` e o histórico do navegador sincronizam o estado da tela sem recarregar a página.
- RF5: As etapas dos workflows possuem links canônicos para agentes e skills associados.
- RF6: Resolução de skills em planos considera tanto o escopo de projeto quanto o catálogo global.

**Não-funcionais**
- Arquivos contidos estritamente abaixo do teto de 250 a 300 linhas (SRP).
- Ausência total de emojis na interface e no código (FontAwesome exclusivo).
- Retrocompatibilidade preservada com parâmetros legados de query string (`?kind=...&id=...`).

## 5. Arquitetura
```
[static.controller.js]       Suporte HTTP para caminhos /catalogo/*
          |
[catalogo-router.js]         Parser, construtor de URLs e orquestrador da History API
          |
[catalogo-page.js]           Coordenador de eventos de rota, abas e detalhe
          |
[catalogo-browser.js]        Navegador de arquivos e árvore com callback de histórico
          |
[catalog-workflows.js]       Descoberta de workflows e enriquecimento de etapas
          |
[workflow-plan.service.js]   Resolução de skills combinando projeto e catálogo global
```
